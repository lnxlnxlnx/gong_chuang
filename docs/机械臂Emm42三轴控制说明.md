# 机械臂 Emm42 三轴控制说明

> 适用对象：三台 ZDT Emm42 闭环步进电机组成的机械臂。
>
> 本文只定义已确认的电机控制事实与安全边界。6、7 轴的毫米换算必须在传动参数确认后才能启用；不得用机械硬限位试探行程。

## 1. 已确认的轴映射

| 轴 | 电机地址 | CW（`Direction.CW` / 字节 `00`） | CCW（字节 `01`） | 对外计量单位 |
|---|---:|---|---|---|
| 底座旋转 | 5 | 顺时针旋转 | 逆时针旋转 | 输出轴角度（°） |
| 上下 | 6 | 向上移动 | 向下移动 | 直线位移（mm，待传动参数） |
| 前后伸缩 | 7 | 向前移动 | 向后移动 | 直线位移（mm，待传动参数） |

上述地址和方向来自当前机械臂实物说明。三个地址必须与底盘的 1--4 地址保持唯一，才可挂在同一条 Emm42 总线上。

## 2. 驱动器的已证实参数

来源：`docs/Emm_V5.0步进闭环驱动说明书Rev1.3.pdf`，印刷页 36--37（PDF 页 37--38）。

| 项目 | 值 | 使用要求 |
|---|---|---|
| 通讯接口 | UART，115200 bps、8N1 | 必须与 USB-TTL 和驱动器菜单一致 |
| 方向编码 | `00` = CW；`01` = CCW | 本机械臂各轴的物理含义见上表 |
| 速度范围 | `0..3000 RPM` | 为避免撞击，机械臂测试用小转速；具体值见 `modules/arm/config.json` 的 `motion.rpm`（当前 `30 RPM`，早期用 `10 RPM` 验证过） |
| 加速度档位 | `0..255` | `0` 为无曲线加减速；机械臂测试建议使用 `5`，不得在未验证前提高 |
| 支持细分 | `1..256`，菜单默认 16 | 软件不能假定为 16；先读取或人工确认每台的 `MStep` |
| 16 细分的脉冲数 | 3200 脉冲/电机圈 | 仅在 1.8° 电机且 `MStep=16` 时成立 |
| 位置模式 | 相对或绝对 | 机械臂测试只能使用相对位置模式 |
| 停止 | `FE 98` | 速度和位置模式均可立即刹车 |

当前 `modules.motor.drive.emm42.Emm42Driver` 默认按 `pulses_per_revolution=3200` 工作。若实际细分不是 16，必须在构造驱动器时传入正确值；否则所有角度、毫米和测试上限都会错误。

## 3. 可复用的 Emm42 命令

| 目的 | 命令格式 | 当前 Python API | 备注 |
|---|---|---|---|
| 使能扭矩 | `ID F3 AB 01 00 6B` | `enable(True)` | 每次位置移动前需要使能 |
| 失能松轴 | `ID F3 AB 00 00 6B` | `enable(False)` | 测试结束和异常清理时执行 |
| 相对位置移动 | `ID FD dir rpm(2B) acc pulses(4B) 00 00 6B` | `move_relative(...)` | 三轴测试唯一允许的运动命令 |
| 绝对位置移动 | `ID FD dir rpm(2B) acc pulses(4B) 01 00 6B` | `move_absolute(...)` / `RobotArm.move_all_to_zero()` | **前提是回过零**（驱动器内部计数器有效）；回零之后用它归位。**脉冲数为 0 是合法的**——那正是"回原点" |
| 立即停止 | `ID FE 98 00 6B` | `stop()` | 紧急停止；之后仍应失能并关闭串口 |
| 总线同步启动 | `00 FF 66 6B` | `trigger_sync_motion()` | 仅多轴协同且各轴行程边界已验证时使用 |
| **触发回零** | `ID 9A mode sync 6B` | `home(mode)` / `RobotArm.home_all()` | mode：`00` 单圈就近、`01` 单圈方向、`02` 多圈碰撞、`03` 多圈限位开关。**前提：已使能扭矩、未触发堵转保护、单圈零点值有效** |
| **设单圈零点** | `ID 93 88 01 6B` | 未封装（用驱动器菜单 `O_Set → Set O` 即可） | 把**当前**姿态设成单圈回零零点，写进驱动器；任意姿态都能设 |
| 清当前位置计数 | `ID 0A 6D 6B` | 未封装 | 只清当前位置/误差/脉冲数，**掉电即失效**；与 `0x93` 不是一回事 |
| 读实时位置 | `ID 36 6B` | 未封装 | 返回 `符号 + 4 字节`；单位为 **65536 = 一圈**，不是脉冲 |
| 读实时转速 | `ID 35 6B` | 未封装 | 返回 `符号 + 转速` |
| 读位置误差 | `ID 37 6B` | 未封装 | 返回 `符号 + 误差值` |
| 读回零参数 | `ID 22 6B` | 未封装 | 返回模式/方向/转速/超时/碰撞阈值/是否上电自动回零 |
| 中断回零 | — | 未封装 | 回零过程中可强制中断退出；手册 6.3.2 有帧格式 |

位置帧的 `pulses` 是 4 字节无符号数，协议上限为 `0xFFFFFFFF`。机械臂封装不能使用这个协议上限作为实际允许范围，必须由每轴的软件行程范围限制。

说明书的通用默认值是 `Response=Receive`，这时会立即返回 `ID FD 02 6B`。本机械臂在 COM29 上读取到的 5、6、7 号配置均为 `Response=None`：控制帧会执行，但不回四字节 ACK。`RobotArm` 因此显式传入 `expect_ack=False`；底盘和其他 `Emm42Driver` 调用仍默认严格验证 ACK。

不要把机械臂的响应方式改为 `Both` 或 `Reached` 后继续使用当前无 ACK 模式；这些设置会在到位后产生 `ID FD 9F 6B`，需要新增到位回包处理后才能安全使用。**但这一条值得做**：回零耗时不确定，而 `RobotArm.home_axis` 现在只能等一个保守时长（`homing.expected_seconds`）；开了到位回包就能换成真正的到位等待。手册 8.1 还写明到位窗口默认 0.3°。

### 3.1 两个"圈"的单位不要混

位置**命令**（`0xFD`）用**脉冲**：手册写明「1.8° 步进电机、16 细分，发送 3200 个脉冲转一圈」，
所以 `pulses_per_revolution = 3200`。

位置**读回**（`0x36`/`0x31` 等）用**编码器单位**：手册注「经过线性化校准后，内部对编码器值
进行了 4 倍频，一圈的数值是 0-65535」，所以 **65536 = 一圈**。两者相差 **20.48 倍**，
换算时极易搞错。

另外 `0x36` 的读数只有**一圈**的量程。手册的例子把 `0x00010000` 算成 `-360.0°`（不取模），
所以它到底是不是多圈计数，手册没有说死——真机验证：断电后手动把轴转过一圈再上电，
读 `0x36` 看值是否体现多圈。**这直接决定单圈回零能不能当可靠的绝对参考。**

## 4. 运动量换算

### 4.1 基础量

令：

- `PPR`：每电机圈脉冲数；16 细分时为 `3200`。
- `g`：电机转数 / 输出轴转数。减速器的常规 “6:1 减速” 对应 `g = 6`，即电机转 6 圈、输出轴转 1 圈。
- `L`：直线机构的每输出轴圈位移（mm/圈）。丝杠为导程；同步带为主动轮有效周长；齿轮齿条为小齿轮节圆周长。

### 4.2 5 号底座轴

`modules/arm/config.json` 当前取 `g = 5`（`axes.base.reduction_ratio`）。装配图上通常记为
“1:6” 之类，含义必须在铭牌上确认；**抓取流程里所有角度命令都依赖它**，差 20% 在
`r = 150 mm` 处就是 30 mm 以上的定位偏差，所以先用实验 A0（见 `docs/抓取坐标链路.md`）
实测一次：命令底座累计走 16000 脉冲，回到原位即 `g = 5`。

```text
输出轴角度(°) = 脉冲数 * 360 / (PPR * g)
脉冲数 = round(|输出轴角度| * PPR * g / 360)
```

在 `PPR=3200` 且 `g=5` 时：

- 输出轴一圈 = `16000` 脉冲；
- 1000 脉冲 = `22.5°` 输出轴转角；
- 1 脉冲 = `0.0225°` 输出轴转角。

（早期文档按 `g=6` 给出的 `19200` 脉冲与 `18.75°` 已作废。）

### 4.3 6、7 号直线轴

在已知 `L` 与 `g` 后：

```text
位移(mm) = 脉冲数 * L / (PPR * g)
脉冲数 = round(|位移(mm)| * PPR * g / L)
```

6 轴与 7 轴必须分别记录自己的 `mm_per_motor_rev = L / g`。公式里永远只出现这个商，所以
**不必拆机分别量 `L` 和 `g`**：直接测「电机转一圈走多少毫米」即可（实验 B/C，见
`docs/抓取坐标链路.md`）。没有这个值时，程序只能报告电机脉冲数与电机转角，
不能声称报告了真实毫米位移。

## 5. 机械臂保守测试边界

测试参数集中在 `modules/arm/config.json`。入口和控制器都会读取同一份配置，并在打开串口前拒绝超出配置范围的输入：

| 参数 | 允许值 | 原因 |
|---|---|---|
| 运动模式 | 仅相对位置模式 | 避免无零点的绝对坐标误动作 |
| 速度 | `motion.rpm`，当前 `30 RPM` | 用户指定的低速测试要求；每个动作可用 `rpm=` 单次覆盖 |
| 加速度 | `motion.acceleration`，当前 `5` | 保守的曲线加减速档位；每个动作可用 `acceleration=` 单次覆盖 |
| 单次脉冲数 | `1..motion.max_pulses`，当前 `1..5000` | `motion.max_pulses`；修改上限时 CLI 与控制器同步生效 |
| 单次方向 | 只允许该轴表中定义的 CW/CCW | 物理方向不可由调用方自由猜测 |
| 多轴同步 | 禁止 | 单轴方向、传动和安全行程未完成验证前不同时运动 |
| 绝对行程 | `limits`，三项都为空时**不做检查** | 抓取流程用 `safe_pose` 与 `limits` 做软件保护；缺项等于没有保护 |

在 16 细分下，1000 脉冲等于电机轴 `112.5°`。当前 `max_pulses=5000` 对底座是输出
`112.5°`（`g=5`）。这不是 6、7 轴的毫米位移；毫米上限必须按第 4 节的实际传动参数计算。

每次真机测试的固定生命周期：使能目标轴 -> 发送一条相对位置帧 -> 保持观察 -> 停止 -> 失能 -> 关闭串口。发生异常或 `Ctrl+C` 时也必须执行停止、失能、关闭。

## 6. 实施前必须确认的机械参数

以下数据在现有 PDF 和项目文档中均未找到，缺失时禁止生成可动真机的毫米 API 或软件行程上限：

| 轴 | 必填数据 | 用途 |
|---|---|---|
| 5 | 减速器铭牌/装配图中“输入转数 : 输出转数”的明确定义；安全转角范围；零位基准与限位方式 | 固化角度换算、拒绝越界旋转 |
| 6 | 丝杠导程或等效 `L`；是否另有减速器；最低/最高机械位置；零位与限位方式 | `mm <-> 脉冲` 换算和上/下行程限制 |
| 7 | 丝杠导程或等效 `L`；是否另有减速器；最短/最长伸出量；零位与限位方式 | `mm <-> 脉冲` 换算和前/后行程限制 |
| 全部 | 每台 `MStep` 细分值、串口端口、供电和急停措施 | 保证脉冲换算和真机通信正确 |

不能用堵转保护或机械碰撞来确定零位、导程、方向或行程。若没有限位开关，首次参数标定必须在远离两端机械止挡的位置开始，并由操作者持续观察。

## 7. 后续封装的验收标准

- 轴 5/6/7 的对象地址分别固定为 5/6/7，CW 物理方向与第 1 节一致。
- 任意测试调用若不是相对位置模式，或脉冲不在 `1..motion.max_pulses`，必须在发送串口帧前抛出 `ValueError`；速度和加速度必须使用配置中的值。
- 在 `MStep=16`、5 轴 `g=5` 的前提下，1000 脉冲必须换算为 `22.5°`。
- 6、7 轴在未提供 `mm_per_motor_rev` 时，只能报告脉冲数和电机转角；不得显示或接受毫米位移，也不得声称已具备软件行程保护。
- 离线测试必须验证帧地址、方向字节、速度、加速度、脉冲上限、换算公式和异常清理路径，且不得打开真实串口。

## 8. 当前实现与真机测试

实现文件：`modules/arm/drive/robot_arm.py`。`RobotArm` 从 `modules/arm/config.json` 读取 5、6、7
三轴地址和运动参数，并共享一条串口总线；没有速度模式，也没有可调用方覆盖的脉冲上限
（`max_pulses` 始终生效）。单次调用的 `rpm`、`acceleration` 可以覆盖配置值，但必须落在驱动器协议范围内。

| 物理动作 | API | 返回值 |
|---|---|---|
| 底座顺/逆时针 | `rotate_cw(pulses, *, rpm=None, acceleration=None, wait=True)` / `rotate_ccw(...)` | 电机角度和基于 `g=5` 的输出轴角度 |
| 向上/下 | `move_up(pulses, ...)` / `move_down(pulses, ...)` | 电机脉冲数与电机角度 |
| 向前/后 | `move_forward(pulses, ...)` / `move_backward(pulses, ...)` | 电机脉冲数与电机角度 |
| **回零** | `home_axis(axis_name, ...)` / `home_all(...)` | 等待的秒数 |
| **归位** | `move_axis_to_zero(axis_name, ...)` / `move_all_to_zero(...)` | 等待的秒数 |
| 全轴安全清理 | `stop_all()`、`disable_all()`、`close()` | 无 |

**回零与归位都按 `伸缩 → 升降 → 底座` 的顺序**（`RobotArm.HOME_ORDER`）：伸出状态下转底座会把
整条臂横扫过工作区。这两件事都要求**已经回过零**——归位走的是绝对模式，依赖驱动器内部的位置
计数器，掉电即失效。调用方必须先 `enable_all()`：手册写明触发回零的前提是"已使能扭矩、
未触发堵转保护、单圈零点值有效"。

两者的等待时长都是**保守估算**（回零按 `homing.expected_seconds`，归位按该轴的行程跨度算最坏
情况），因为 `Response=None` 时这两件事结束都没有回包。开到位回包后可以换成真正的到位等待。

另有一组**带符号的单位制**动作，抓取流程用这一组（它算出来的是"从当前位姿到目标位姿的差"）。
正数对应同一个 CW 方向，负数自动反向：

| 物理动作 | API | 前置条件 |
|---|---|---|
| 转动底座 | `move_base_degrees(degrees, ...)` | 需要 `axes.base.reduction_ratio` |
| 升降 | `move_lift_mm(millimeters, ...)` | 需要 `axes.lift.mm_per_motor_rev` |
| 伸缩 | `move_radial_mm(millimeters, ...)` | 需要 `axes.extension.mm_per_motor_rev` |

两组都**不检查绝对行程**：行程是绝对位姿的限制，调用方必须在发出动作前用
`modules.arm.drive.kinematics.require_reachable` 检查（抓取流程就是这么做的）。
单位制动作里位移不足半个脉冲时既不发帧也不等待，调用方应当把它当成"已经到位"。

参数约定与底盘轮子完全一致（见 `modules/motor/drive/motion.py`）：`pulses` 必填、`rpm` / `acceleration` 可选、
`wait=True`（默认）等到动作走完再返回。**这一条很重要**：5/6/7 号驱动器是 `Response=None`，
控制帧没有 ACK、也没有到位回包，不等待就会在下一条位置帧发出时覆盖上一条的目标，现象是
"上一个动作没执行完"。`wait` 的实现是按说明书公式估算耗时：

```
总耗时 ≈ rpm * (256 - acceleration) * 50µs + 脉冲数 / (rpm * 脉冲每圈 / 60) + 到位余量(0.15s)
```

返回值 `MotionReport` 里的 `estimated_seconds` 就是这个估算值；`wait=False` 时调用方可以
自己拿它去等（比如要同时准备其它动作）。这是估算而不是编码器实测，需要毫秒级精确时要用
`0x3A` 读运动状态标志（`&0x02` 到位位）轮询，当前没有实现。

在项目根目录运行统一测试菜单并选择机械臂；串口从 `modules/motor/config.json`（步进总线唯一来源）读取。每个动作走 `modules/arm/config.json` 里的 `motion.default_pulses`，每步都需要操作员回车确认，输入 `q` 停止后续动作。正常结束、异常和 `Ctrl+C` 都会停止三轴、失能并关闭串口。

```powershell
python test.py
```

预期：选择 2 后，终端依次询问底座顺/逆时针、向上/下、向前/后六个动作；每次只发送一条地址为 5、6 或 7 的 `FD` 相对位置帧，速度、加速度和默认脉冲均来自 `modules/arm/config.json`，并且**每条命令后都会等估算耗时走完才问下一个动作**（所以动作会一个接一个地真正做完，不会互相打断）。动作表末尾有“确认机械臂后缩完成”的空动作：它不会发送串口帧，只等待确认，使后缩完成后才停止、失能、关闭串口。因为当前驱动器设置为 `Response=None`，该脚本不会等待 ACK。

预期：当配置中的默认脉冲超过 `motion.max_pulses` 时，程序会在打开串口前拒绝配置，不发送运动帧。
