# 机械臂 Emm42 三轴控制说明

> 适用对象：三台 ZDT Emm42 闭环步进电机组成的机械臂。
>
> 本文只定义已确认的电机控制事实与安全边界。6、7 轴的毫米换算必须在传动参数确认后才能启用；不得用机械硬限位试探行程。

## 1. 已确认的轴映射

| 轴 | 电机地址 | CW（`Direction.CW` / 字节 `00`） | CCW（字节 `01`） | 对外计量单位 |
|---|---:|---|---|---|
| 底座旋转 | 5 | 顺时针旋转 | 逆时针旋转 | 输出轴角度（°） |
| 上下 | 6 | 向上移动 | 向下移动 | 直线位移（mm，待传动参数） |
| 前后伸缩 | 7 | 向前移动 | 向后移动 | 直线位移（mm，待传动参数） |

上述地址和方向来自当前机械臂实物说明。三个地址必须与底盘的 1--4 地址保持唯一，才可挂在同一条 Emm42 总线上。

## 2. 驱动器的已证实参数

来源：`docs/Emm_V5.0步进闭环驱动说明书Rev1.3.pdf`，印刷页 36--37（PDF 页 37--38）。

| 项目 | 值 | 使用要求 |
|---|---|---|
| 通讯接口 | UART，115200 bps、8N1 | 必须与 USB-TTL 和驱动器菜单一致 |
| 方向编码 | `00` = CW；`01` = CCW | 本机械臂各轴的物理含义见上表 |
| 速度范围 | `0..3000 RPM` | 为避免撞击，机械臂测试固定使用 `10 RPM` |
| 加速度档位 | `0..255` | `0` 为无曲线加减速；机械臂测试建议使用 `5`，不得在未验证前提高 |
| 支持细分 | `1..256`，菜单默认 16 | 软件不能假定为 16；先读取或人工确认每台的 `MStep` |
| 16 细分的脉冲数 | 3200 脉冲/电机圈 | 仅在 1.8° 电机且 `MStep=16` 时成立 |
| 位置模式 | 相对或绝对 | 机械臂测试只能使用相对位置模式 |
| 停止 | `FE 98` | 速度和位置模式均可立即刹车 |

当前 `motor_drivers.emm42.Emm42Driver` 默认按 `pulses_per_revolution=3200` 工作。若实际细分不是 16，必须在构造驱动器时传入正确值；否则所有角度、毫米和测试上限都会错误。

## 3. 可复用的 Emm42 命令

| 目的 | 命令格式 | 当前 Python API | 备注 |
|---|---|---|---|
| 使能扭矩 | `ID F3 AB 01 00 6B` | `enable(True)` | 每次位置移动前需要使能 |
| 失能松轴 | `ID F3 AB 00 00 6B` | `enable(False)` | 测试结束和异常清理时执行 |
| 相对位置移动 | `ID FD dir rpm(2B) acc pulses(4B) 00 00 6B` | `move_relative(...)` | 三轴测试唯一允许的运动命令 |
| 绝对位置移动 | `ID FD dir rpm(2B) acc pulses(4B) 01 00 6B` | `move_absolute(...)` | 未完成可靠回零和软件坐标建立前禁止用于机械臂 |
| 立即停止 | `ID FE 98 00 6B` | `stop()` | 紧急停止；之后仍应失能并关闭串口 |
| 总线同步启动 | `00 FF 66 6B` | `trigger_sync_motion()` | 仅多轴协同且各轴行程边界已验证时使用 |

位置帧的 `pulses` 是 4 字节无符号数，协议上限为 `0xFFFFFFFF`。机械臂封装不能使用这个协议上限作为实际允许范围，必须由每轴的软件行程范围限制。

说明书的通用默认值是 `Response=Receive`，这时会立即返回 `ID FD 02 6B`。本机械臂在 COM29 上读取到的 5、6、7 号配置均为 `Response=None`：控制帧会执行，但不回四字节 ACK。`RobotArm` 因此显式传入 `expect_ack=False`；底盘和其他 `Emm42Driver` 调用仍默认严格验证 ACK。

不要把机械臂的响应方式改为 `Both` 或 `Reached` 后继续使用当前无 ACK 模式；这些设置会在到位后产生 `ID FD 9F 6B`，需要新增到位回包处理后才能安全使用。

## 4. 运动量换算

### 4.1 基础量

令：

- `PPR`：每电机圈脉冲数；16 细分时为 `3200`。
- `g`：电机转数 / 输出轴转数。减速器的常规 “6:1 减速” 对应 `g = 6`，即电机转 6 圈、输出轴转 1 圈。
- `L`：直线机构的每输出轴圈位移（mm/圈）。丝杠为导程；同步带为主动轮有效周长；齿轮齿条为小齿轮节圆周长。

### 4.2 5 号底座轴

用户给出的减速比记为 “1:6”，其输入输出方向必须在装配图或铭牌上确认。只有确认其含义是 6:1 减速（`g=6`）时，才使用：

```text
输出轴角度(°) = 脉冲数 * 360 / (PPR * 6)
脉冲数 = round(|输出轴角度| * PPR * 6 / 360)
```

在 `PPR=3200` 且 `g=6` 时：

- 输出轴一圈 = `19200` 脉冲；
- 1000 脉冲 = `18.75°` 输出轴转角；
- 1 脉冲 = `0.01875°` 输出轴转角。

### 4.3 6、7 号直线轴

在已知 `L` 与 `g` 后：

```text
位移(mm) = 脉冲数 * L / (PPR * g)
脉冲数 = round(|位移(mm)| * PPR * g / L)
```

6 轴与 7 轴必须分别记录自己的 `L` 和 `g`。没有这两个参数时，程序只能报告电机脉冲数与电机转角，不能声称报告了真实毫米位移。

## 5. 机械臂保守测试边界

测试参数集中在 `config/robot_arm.json`。入口和控制器都会读取同一份配置，并在打开串口前拒绝超出配置范围的输入：

| 参数 | 允许值 | 原因 |
|---|---|---|
| 运动模式 | 仅相对位置模式 | 避免无零点的绝对坐标误动作 |
| 速度 | 初始值 `10 RPM` | `motion.rpm`；用户指定的低速测试要求 |
| 加速度 | 初始值 `5` | `motion.acceleration`；保守的曲线加减速档位 |
| 单次脉冲数 | `1..motion.max_pulses`，初始 `1..1000` | `motion.max_pulses`；修改上限时 CLI 与控制器同步生效 |
| 单次方向 | 只允许该轴表中定义的 CW/CCW | 物理方向不可由调用方自由猜测 |
| 多轴同步 | 禁止 | 单轴方向、传动和安全行程未完成验证前不同时运动 |

在 16 细分下，1000 脉冲等于电机轴 `112.5°`。这不是 6、7 轴的毫米位移；毫米上限必须按第 4 节的实际传动参数计算。

每次真机测试的固定生命周期：使能目标轴 -> 发送一条相对位置帧 -> 保持观察 -> 停止 -> 失能 -> 关闭串口。发生异常或 `Ctrl+C` 时也必须执行停止、失能、关闭。

## 6. 实施前必须确认的机械参数

以下数据在现有 PDF 和项目文档中均未找到，缺失时禁止生成可动真机的毫米 API 或软件行程上限：

| 轴 | 必填数据 | 用途 |
|---|---|---|
| 5 | 减速器铭牌/装配图中“输入转数 : 输出转数”的明确定义；安全转角范围；零位基准与限位方式 | 固化角度换算、拒绝越界旋转 |
| 6 | 丝杠导程或等效 `L`；是否另有减速器；最低/最高机械位置；零位与限位方式 | `mm <-> 脉冲` 换算和上/下行程限制 |
| 7 | 丝杠导程或等效 `L`；是否另有减速器；最短/最长伸出量；零位与限位方式 | `mm <-> 脉冲` 换算和前/后行程限制 |
| 全部 | 每台 `MStep` 细分值、串口端口、供电和急停措施 | 保证脉冲换算和真机通信正确 |

不能用堵转保护或机械碰撞来确定零位、导程、方向或行程。若没有限位开关，首次参数标定必须在远离两端机械止挡的位置开始，并由操作者持续观察。

## 7. 后续封装的验收标准

- 轴 5/6/7 的对象地址分别固定为 5/6/7，CW 物理方向与第 1 节一致。
- 任意测试调用若不是相对位置模式，或脉冲不在 `1..motion.max_pulses`，必须在发送串口帧前抛出 `ValueError`；速度和加速度必须使用配置中的值。
- 在 `MStep=16`、5 轴 `g=6` 的前提下，1000 脉冲必须换算为 `18.75°`。
- 6、7 轴在未提供 `L`、`g`、零位和行程范围时，只能报告脉冲数和电机转角；不得显示或接受毫米位移，也不得声称已具备软件行程保护。
- 离线测试必须验证帧地址、方向字节、速度、加速度、脉冲上限、换算公式和异常清理路径，且不得打开真实串口。

## 8. 当前实现与真机测试

实现文件：`robot_arm.py`。`RobotArm` 从 `config/robot_arm.json` 读取 5、6、7 三轴地址和运动参数，并共享一条串口总线；没有速度模式、绝对位置模式或可调用方覆盖的单次速度、加速度、脉冲上限。

| 物理动作 | API | 返回值 |
|---|---|---|
| 底座顺/逆时针 | `rotate_cw(pulses)` / `rotate_ccw(pulses)` | 电机角度和基于 `g=6` 的输出轴角度 |
| 向上/下 | `move_up(pulses)` / `move_down(pulses)` | 电机脉冲数与电机角度 |
| 向前/后 | `move_forward(pulses)` / `move_backward(pulses)` | 电机脉冲数与电机角度 |
| 全轴安全清理 | `stop_all()`、`disable_all()`、`close()` | 无 |

在 Jetson 上从项目根目录执行真机脚本。`--port` 必填；当前默认每个动作走 600 脉冲，每步都需要操作员回车确认，输入 `q` 停止后续动作。正常结束、异常和 `Ctrl+C` 都会停止三轴、失能并关闭串口。

```powershell
python -m hardware_tests.arm.position_motion --port /dev/ttyUSB0
```

预期：终端依次询问底座顺/逆时针、向上/下、向前/后六个动作；每次只发送一条地址为 5、6 或 7 的 `FD` 相对位置帧，速度、加速度和默认脉冲均来自 `config/robot_arm.json`（初始为 10 RPM、5、600）。动作表末尾有“确认机械臂后缩完成”的空动作：它不会发送串口帧，只等待确认，使后缩完成后才停止、失能、关闭串口。因为当前驱动器设置为 `Response=None`，该脚本不会等待 ACK。

需要改变测试范围时，只修改 `config/robot_arm.json` 的 `motion.default_pulses` 与 `motion.max_pulses`；前者必须不大于后者。需要在用户确认机械行程安全后才提高上限：

```powershell
python -m hardware_tests.arm.position_motion --port /dev/ttyUSB0 --pulses 1000
```

预期：参数超出配置的 `1..motion.max_pulses` 时命令行立即拒绝，不发送任何运动帧。
