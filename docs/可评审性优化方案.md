> 目标：让上层通过少量明确的类接口调用视觉与抓取，设备由对象管理，内部实现便于理解和验证。

## 1. 已明确的需求

本轮讨论已明确三项要求：

1. **重点优化视觉、抓取两个模块**，首先解决不适合被上层调用的问题。
2. 对外采用清晰的 `类名.方法(...)` 形式；无状态操作可用静态方法，构造使用类方法，有连接和会话状态的操作使用实例方法。
3. **视觉/抓取对象负责打开、关闭设备，上层只传配置并调用方法。** 不让调用者每次组装相机、定位器、机械臂、观测源和一组标定参数。

因此，重构重点从“拆大文件、减代码行数”调整为“形成可直接使用的模块接口”。内部拆分只服务于这个目标。

## 2. 目标调用方式

以下为**拟议接口示例，当前源码尚不支持**。配置仍使用现有文件和字段，不新建配置格式。

视觉独立使用，预期只需导入一个入口类、提供配置、读取结构化结果：

```python
from modules.vision import Vision

with Vision.open(config_path="modules/vision/config.json") as vision:
    report = vision.locate()
    if report.best is not None:
        print(report.best.x_mm, report.best.y_mm, report.best.z_mm)
```

抓取主线，预期由对象读取标定并管理机械臂与内部视觉会话：

```python
from modules.grasp import Grasp

with Grasp.open(
    config_path="modules/grasp/eye_in_hand.json",
    vision_config_path="modules/vision/config.json",
) as grasp:
    result = grasp.align_and_descend()
```

示例中的 `open()` 为类方法，返回已就绪、拥有设备资源的实例，支持 `with` 和显式 `close()`。`locate()`、`align_xy()`、`align_and_descend()` 使用实例状态，不做成持有隐式全局设备的静态方法。

`align_and_descend()` 只完成现有的对准、下降、后缩流程，**不意味着夹爪闭合或物料搬运完成**。不新增名为 `pick()` 的不完整承诺。

详细参数、异常、资源归属、配置路径和返回值见专项 §2–§5。

## 3. 当前调用障碍与事实修正

### 3.1 需要优先解决的问题

| 障碍 | 当前证据 | 目标 |
|---|---|---|
| 视觉资源装配在抓取模块 | `grasp/drive/camera_source.py` 同时创建相机、模型定位器、转换观测和管理资源 | 相机、模型及本地观测由视觉模块实际拥有，依赖方向为 grasp → vision |
| 抓取函数参数多 | `align_and_descend()` 要求 arm、source、selector、target、jacobian、config 等 | 参数在会话创建时从配置装配，日常操作只给本次必要覆盖值 |
| 可复用流程藏在 CLI | `grasp/test/manual/align_xy.py:main()` 装配配置、资源并分发流程 | 普通动作的资源生命周期进入 `Grasp`，CLI 负责参数和交互 |
| 视觉包出口庞杂 | `vision/__init__.py` 维护惰性表、类型声明、导出列表与工厂函数 | 只提供少量有明确用途的公开类与结果/异常；内部直接引用定义处 |
| 自测与真实 CLI 混合 | 多个 `drive/*.py` 同时有 `_self_test()`、图片和相机入口 | 自测去重或迁移，真实工具用途和检查独立保留 |
| 测试之间借用夹具 | 多个 `test_*.py` 导入另一用例文件的假设备 | 提取实际共享件，保留专用设备假件 |

### 3.2 原方案中不再沿用的结论

- `PointCloud.save_csv()` 正被菜单 16、17 调用，移出待删名单。
- 两个 `pulses_for()` 分别属于二维雅可比和一维升降尺度，不是重复函数。
- `WheelPosition` 当前没有原文提到的 dataclass 装饰器，删除过时整改项。
- `DistanceEstimator` 被视觉包直接导出，`map.py` / `demo_chassis` 有单测调用；不能写成全仓零引用。
- `safe_lift_angle_degrees` 没有动作读取，不等于“没有转动前抬升保护”：`align_x_y()` 默认无条件先调用 `raise_before_rotating()`。
- `test_camera_source.py` 已检查深度、直径、边缘百分比与时间戳换算，不能称这些换算没有测试。
- 仅把函数搬文件不会降低函数内复杂度；既有测试通过也不能单独证明 CLI 和真机行为等价。

## 4. 本轮方案的范围

### P0：形成视觉与抓取的可调用接口

- `Vision` 实际负责相机、定位器/模型、本地取帧及观测结果；同一会话复用设备和模型。
- `Grasp` 实际负责机械臂、内部视觉会话、选择条件、目标、雅可比和升降尺度；保持现有动作流程。
- 上层导入公开类即可使用，不从 `test/manual/`、内部 `drive` 子文件或私有助手拼装正常流程。
- 保留已有结构化结果，不增加一套为了门面而存在的重复结果类型；不解析中文 `summary()` 作为本地业务数据。
- 原有配置路径可显式指定；默认值仍来自模块自己的现有配置，不能受运行目录影响。
- 新接口承载真实实现和资源所有权，不只是包一层旧函数；同批迁移调用方，不保留兼容转发和双入口。

### P1：为接口收敛做必要的内部调整

- `eye_in_hand` 按配置/数值模型、观测、脉冲原语、实际控制职责整理；避免按“测量/平面/z”机械切分造成互相导入。
- `Grasp` 的真实会话和主编排置于 `grasp/runtime.py`，显式动作时才加载 eye_in_hand 算法，保留原自测 CLI 且避免包导入的 runpy 预加载冲突。
- 原 `camera_source` 的本地相机装配和观测能力迁入视觉模块；抓取保留窄观测接口，以继续支持当前显式 TCP 来源和离线假件。
- 菜单 18、21 与 `main.py` 中对应场景迁移到新接口。图片工具仍走已有帧级定位器；不为了使用相机会话而让离线图片处理打开硬件。
- CLI 与 demo 的模型、相机、焦距、颜色等本次覆盖先应用到配置快照，再进入同一真实会话创建路径；不写回配置、不另开设备。预览在模块内部复用会话拥有的相机和定位器，保留原 `run_preview` 两线程、绘制与回调，不把同步定位塞进显示循环。
- 按现有场景核对自测覆盖，允许测试 import 与 patch 随实际定义迁移；保留真实 CLI 的运行检查。
- 仅提取确实重复的测试辅助；不换 unittest、不新增依赖、不要求所有假串口合成一个。

### P2：与主目标分开的历史清理

原方案记录菜单 19 已退役、`laser_scan` 已被 D6 取代。保留这两项清理范围，放在独立批次；**不作为视觉/抓取接口可用的前提**。

其余全仓清理、底盘门面改造、训练目录迁移、通用配置框架与全仓静态方法改写均不纳入本次重点。

## 5. 不得改变的业务契约

| 契约 | 验收要求 |
|---|---|
| 主链顺序 | 悬停 → 确认安全高度 → x/y 对准 → 下降 → 后缩；失败时不继续后续动作 |
| 转动前高度 | 保留默认抬升与明确高度前提下的跳过检查；不新增角度阈值来放宽现有保护 |
| 下降语义 | 固定脉冲下降；平面未对准时零下降动作，不宣称有闭环深度保护 |
| 观测时序 | 保留动作后新帧、停稳、可见性、迭代和脉冲预算判据；不把取到结果的时刻伪装成拍摄时刻 |
| 数学与单位 | 坐标正方向、毫米、像素、直径、百分比和斜距含义不变 |
| 视觉策略 | 保留现有颜色/霍夫/分类判据及现有策略顺序；不新增兜底，不顺带更换算法 |
| 升降尺度 | `LiftScale` 仍用于悬停、安全抬升、探针和下降信息，不随视觉 z 工具一起删除 |
| 资源与副作用 | 导入类不读配置、不开设备；普通动作前校验配置和必要标定；正常和异常路径均释放所有已获取资源 |
| 现场配置 | 端口、地址、标定和调参值不变，必要注释保留；不重新发明默认值 |

新的公开接口可以改变组织与调用形式，不能借此改变动作规则、配置接受范围或异常所代表的失败原因。若发现现有行为缺陷，单列修复及验收。

### 6.1 基线的可信边界

原方案记录过 `collected 962 / failures 1 / errors 165 / skipped 1`，没有完整原始日志和可重建环境，**只能作为历史观察，不能称为当前实测基线**。本轮采用静态审阅，不运行套件或硬件。

- 编码测试应显式用子解释器 `-X utf8`，父进程按 UTF-8 严格解码；已有 `errors="replace"` 不是修复。
- 不在 `test.py.main()` 中直接加 `stdout.reconfigure()`：现有测试用 `StringIO` 重定向，它没有该方法。
- `scratch_directory()` 仍依赖 `tempfile.gettempdir()`；先区分临时根不可用、目录权限和清理失败，不能承诺换 helper 就消除历史全部错误。
- 不设测试减到 600 个、单文件小于某行数、假件只留一份等指标。合并测试后必须仍有独立预期，不能让被测函数生成全部预期结果。

## 8. 风险与回滚

| 风险 | 必须达到的条件 |
|---|---|
| 外观简单但仍要上层拼十几个对象 | 普通视觉和抓取示例只传配置，设备只在会话内创建和管理 |
| 静态方法持有全局硬件 | 连接、模型和本次状态归属实例；无单例、全局缓存和隐式最近会话 |
| 把新类做成旧函数的转发壳 | 新类持有真实实现、资源和流程；旧公开入口在消费者迁移时退出 |
| 包初始化引发循环或 runpy 警告 | 少量显式出口，不预导入 CLI 模块；所有公开入口和现存 CLI 均验证 |
| 模块移动改变配置路径或类身份 | 路径仍锚定原模块配置；类型单一定义；调用方和 patch 同批迁移 |
| 清理一步失败阻断后续释放 | 所有已获得资源均尝试释放；保留原异常信息并让清理失败可见，不能静默吞掉 |
| 现有未提交代码被覆盖 | 实施前区分用户修改和本批范围；每批独立提交，仅回滚本批，不覆盖其他工作 |
