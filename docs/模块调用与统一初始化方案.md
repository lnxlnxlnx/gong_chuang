## 1. 当前哪些操作已经可以这样调用

下表中的动作方法都已经存在。除 Vision/Grasp 示例外，表中的变量指已经正确创建、初始化和使能的对象；目前项目还没有一个总入口完成这些装配。

| 模块 | 实际对象 | 已有调用 | 单位/结果 |
|---|---|---|---|
| 机械臂 | RobotArm | `arm.move_up(pulses=800)` / `move_down(pulses=800)` | 相对运动，单位为脉冲 |
| 机械臂 | RobotArm | `arm.move_forward(pulses=800)` / `move_backward(pulses=800)` | 前伸/后缩，相对脉冲 |
| 机械臂 | RobotArm | `arm.rotate_cw(pulses=800)` / `rotate_ccw(pulses=800)` | 底座转动，相对脉冲 |
| 机械臂 | RobotArm | `arm.move_base_degrees(10)` | 相对转角，度；正值对应 CW |
| 机械臂 | RobotArm | `arm.move_lift_mm(10)` / `move_radial_mm(10)` | 相对毫米；当前两条直线轴的 mm_per_motor_rev 尚未配置，不能直接运行毫米运动 |
| 夹爪 | GripperServo | `gripper.open_jaws()` / `close_jaws()` | 使用既有开合位置和时长，返回 GripperReport |

| 抓取就位 | Grasp | `grasp.align_xy()` / `align_and_descend()` | 已有视觉伺服流程，后者仍不闭合夹爪 |

动作参数必须按现场空间和配置选取。表中的 800/30/1 只说明调用格式，不是新的默认值，也不代表已完成真机验证。

### 1.1 视觉现在就有完整的简短入口

```python
from modules.vision import Vision

with Vision.open() as vision:
    report = vision.locate()
    if report.best is not None:
        material = report.best
        print(material.x_mm, material.y_mm, material.z_mm)
```

这是相机坐标：X 向右、Y 向下，Z 为沿光轴深度，单位毫米。它不是机械臂基座坐标，不能直接当成 `arm.move_to(x, y, z)` 的目标。没有物料时 best 为 None；读不到画面会报错。

### 1.2 夹爪现在也有对象接口，但装配还需自己写

```python
from modules.servo.drive.bus_servo import load_bus_config
from modules.servo.drive.gripper import GripperServo

bus = load_bus_config()
with GripperServo(bus.port, bus_config=bus) as gripper:
    report = gripper.open_jaws()
    print(report.position, report.reached)
```

`close_jaws()` 表示闭爪，`close()` 表示关闭连接；统一入口保留这个区别。未达到闭合位置可能由多种原因引起，不能仅靠 reached=False 承诺“已经夹到物料”。

### 1.3 抓取就位现在可以独立调用

```python
from modules.grasp import Grasp

with Grasp.open() as grasp:
    result = grasp.align_and_descend()
```

这一入口自行创建机械臂和视觉。**当前不能同时独立打开同一设备的 Vision、RobotArm、Grasp，或分别打开共用步进串口的 arm/chassis。** 以下统一入口需要解决它们的所有权，不能直接把上面几个示例拼成一个程序。

## 2. 新增统一入口的目标用法（尚未实现）

在项目根提供一个可导入的 `Robot` 类，它就是上层模块管理类，负责批量开启、共享设备装配和全部关闭。每个 with 创建一个明确的机器人会话，上层使用它持有的真实模块对象。类可供全项目导入；设备状态放在实例中，不使用静态单例或“最近一次初始化”的全局变量，也不再增加一个重复的 RobotManager 类。

以下代码是新接口的验收示例，**当前还不能复制运行**。动作行展示独立能力，不能把此示例当成现场动作顺序。

一键开启并在结束时关闭全部模块：

```python
from robot import Robot

with Robot.open_all() as robot:
    report = robot.vision.locate()
```

这里的“全部”固定为本轮的 arm、gripper、vision、chassis 四个设备模块，加 grasp 抓取流程；grasp 借用其中的 arm/vision，不再打开第二份设备。一键开启要求这些模块各自的启动配置有效，包括抓取 target/Jacobian；任一项失败就清理已打开资源并抛错，不静默跳过模块。open_all 不自动回零、移动或开闭爪。

需要显式控制关闭时，使用同一个管理实例：

```python
from robot import Robot

robot = Robot.open_all()
try:
    report = robot.vision.locate()
finally:
    robot.close()  # 关闭本实例管理的全部模块及自有连接
```

按需开启则指定本次需要的模块：

```python
from robot import Robot

with Robot.open(arm=True, gripper=True, vision=True, chassis=True) as robot:
    robot.arm.move_up(pulses=800)
    robot.gripper.open_jaws()
    report = robot.vision.locate()
    robot.chassis.forward(rpm=30, duration=1)
```

只使用机械臂时，上层也只需选择该模块：

```python
from robot import Robot

with Robot.open(arm=True) as robot:
    robot.arm.move_up(pulses=800)
```

四个设备模块与 grasp 选择参数均默认 False，至少明确选择一个；未选择且未被 grasp 依赖的模块，属性访问直接报出未启用，不在动作时偷偷打开设备。`Robot.open` 统一处理配置读取、连接、初始化和使能；不做回零、开闭爪、对准、抬升或底盘移动。这些动作仍由上层明确调用。

机械臂两种坐标移动的目标用法如下。两条移动均是**绝对位置**，不是本次增量；数值只演示格式，实际使用必须符合现场标定和行程。

```python
from robot import Robot

with Robot.open(arm=True) as robot:
    robot.arm.home_all()  # 显式回零，采用配置中的实测参考位
    robot.arm.move_cylindrical(base_degrees=30, radial_mm=100, height_mm=60)
    robot.arm.move_to(x_mm=100, y_mm=0, z_mm=60)
```

上层不需要自己调用逆解、算脉冲、记录当前位置或选择各轴动作顺序。既有 `move_up(pulses=...)` 等相对动作仍直接使用，含义和单位不变。

需要现有抓取就位流程时，使用同一总入口的明确选项：

```python
from robot import Robot

with Robot.open(grasp=True, gripper=True) as robot:
    result = robot.grasp.align_and_descend()
    report = robot.gripper.close_jaws()  # 是否闭爪由业务显式决定
```

`grasp=True` 明确包含 arm、vision 两项依赖；不包含 gripper，不自动执行回零或闭爪。`robot.grasp` 与 `robot.arm`、`robot.vision` 使用同一批对象。抓取成功返回不等于夹爪抓到了物料。

`main.py` 只保留业务动作，`test.py` 的菜单继续选择对应测试入口。展示菜单、import 模块、运行离线测试时都不调用 Robot.open。测试脚本里的询问与打印留在脚本；模块方法不调用 input。

### 2.1 固定公开入口，不让执行 agent 自行选命名

| 接口 | 契约 |
|---|---|
| `Robot.open(*, arm=False, gripper=False, vision=False, chassis=False, grasp=False, arm_config_path=None, motor_config_path=None, servo_config_path=None, vision_config_path=None, vision_calibration_path=None, chassis_config_path=None, grasp_config_path=None)` | 类方法，返回就绪实例；`None` 使用对应模块现有默认文件，不新增总配置文件 |
| `Robot.open_all(*, arm_config_path=None, motor_config_path=None, servo_config_path=None, vision_config_path=None, vision_calibration_path=None, chassis_config_path=None, grasp_config_path=None)` | 类方法，固定启用上述五项；配置参数与 open 同名同义，内部复用 open 的唯一装配，不复制初始化逻辑 |
| `robot.arm / gripper / vision / chassis / grasp` | 返回实际模块实例；未启用时抛 RuntimeError；关闭后取用或调用均明确失败 |
| `robot.close()`、上下文管理 | 幂等释放；有业务异常时保留原异常，清理异常作为 cause，不吞错 |
| `arm.move_cylindrical(*, base_degrees, radial_mm, height_mm, rpm=None, acceleration=None)` | 绝对圆柱目标，单位度 / 毫米；按配置估时等待，不提供新的异步选项 |
| `arm.move_to(*, x_mm, y_mm, z_mm, rpm=None, acceleration=None)` | 绝对基座 XYZ，单位毫米；转换后进入同一圆柱运动实现 |
| `arm.move_cylindrical_by(*, base_degrees=0.0, radial_mm=0.0, height_mm=0.0, rpm=None, acceleration=None)` | **相对**圆柱增量，单位度 / 毫米；不需要位姿已知；执行顺序固定"抬升在前、下降最后、平面先伸缩后底座"，返回按执行顺序且只含真的发帧的段 |
| `arm.move_by(*, x_mm=0.0, y_mm=0.0, z_mm=0.0, rpm=None, acceleration=None)` | **相对**基座 XYZ 增量，单位毫米；z 不需要位姿，x/y 需要当前位姿（极坐标分解依赖方位与半径），位姿未知时抛 RuntimeError 且不发帧 |
| `robot.grasp.align_xy(*, hover=False, ensure_safe_height=False)` | 单独对准；**默认一步都不动高度**（悬停会自己升降，物块放高时会顶到行程端点）。代价是转底盘前的安全高度检查也默认关掉，调用方必须先自己够高，或显式传 `ensure_safe_height=True` |
| `robot.grasp.align_and_descend(*, z_pulses=None, retract_pulses=None, hover=True, ensure_safe_height=True)` | 一键就位；默认仍是"悬停 + 查安全高度"，两个开关含义同上 |
| `arm.pose` | 只读 Optional[CylindricalPose]，为夹持点的当前推算位置，未知为 None；调用者不能自行写值 |
| 两个绝对移动方法的返回值 | 沿用不可变 CylindricalPose，返回按实际下发脉冲推算的位置，不新增一套结果类型，不宣称物理到位 |

servo_config_path 同时传给现有舵机总线与夹爪配置加载器；chassis 按当前平台选择现有 windows/jetson profile。路径覆盖只对本次会话生效，并传到真实构造器，不写回文件。模块只导入自己本次需要的依赖，单独启用 arm 不预加载 cv2/模型。新增方法、类与坐标换算要写清单位、参考点、相对/绝对、返回值和失败条件的注释。

### 2.2 各上层类统一的生命周期

适用于 Robot、RobotArm、GripperServo、MecanumChassis、Vision、Grasp。统一同用途参数和行为，模块特有配置仍用明确的具名参数；不增加统一基类、设备注册器或任意 `**kwargs` 转发。

| 方法/属性 | 固定约定 |
|---|---|
| `Class.open(*, ...) -> Class` | 类方法，参数全为关键字；完成配置校验、资源取得和必要使能，返回就绪实例；失败即抛错并释放已取得资源 |
| `close(self) -> None` | 无业务参数；按所有权释放资源，调用后 closed=True；重复调用不重复发命令、失能或关连接；不接收 force、wait、silent 等开关 |
| `closed: bool` | 只读属性；会话关闭后为 True，动作方法统一抛 RuntimeError，不自动重开；内部尚未装配完成的对象不能对外充当就绪对象 |
| `__enter__(self) -> Class` | 校验已就绪并返回 self，不重新读配置、打开连接、初始化或使能；已关闭则抛 RuntimeError |
| `__exit__(self, exc_type, exc_value, traceback) -> bool` | 调用 close；正常清理返回 False；清理异常必须可见，已有业务异常时保留它并挂接清理异常 cause |
| `stop(self) -> None` | 仅 RobotArm、MecanumChassis、GripperServo 提供，停止本模块的执行器；不关闭连接、不额外失能；机械臂位置随停止失效 |

上层使用 `open()` 创建。上层 `__init__` 只接收配置快照/已装配依赖并保存状态，不触发设备 I/O；底层驱动构造器现有行为不因这一约定一并改写。上层不再保留第二套 `initialize()` 创建入口，所有调用者同步迁至 open 或内部快照装配；驱动层的 initialize 继续供真实装配使用。Arm 原 stop_all 更名为 stop，消费者同步迁移，不留旧别名。Vision、Grasp 不增加没有对应行为的 stop 方法。

配置参数统一接受 str、Path 或 None；None 使用模块自身的现有默认配置位置，自定义路径规则和模型相对路径规则沿用现有实现。类型注解须兼容 Python 3.8。固定各模块的公开 open 参数如下：

| 类 | 固定签名与配置含义 |
|---|---|
| `RobotArm` | `open(*, config_path=None, motor_config_path=None)`；分别为 arm 主配置、motor 总线配置 |
| `GripperServo` | `open(*, config_path=None)`；同一 servo 配置同时提供夹爪参数与舵机总线参数，不再传 port 与 bus_config |
| `MecanumChassis` | `open(*, config_path=None, motor_config_path=None)`；分别为 chassis 配置、motor 总线配置；沿用当前平台 profile |
| `Vision` | `open(*, config_path=None, calibration_path=None)`；分别为 vision 主配置与视觉标定；沿用已有接口 |
| `Grasp` | `open(*, config_path=None, vision_config_path=None, vision_calibration_path=None, arm_config_path=None, motor_config_path=None)`；沿用已有独立会话配置职责 |
| `Robot` | 沿用 §2.1 的模块选择和具名配置路径；没有总配置文件，因此不虚设 config_path |

config_path 在每个模块中都只表示该模块的主配置；motor_config_path 在 arm、chassis、grasp、Robot 中都表示同一类步进总线配置。calibration_path 只在 Vision 内可省略 vision 前缀；Grasp/Robot 组合多个模块时用 vision_calibration_path，避免歧义。资源注入使用显式内部装配参数；不要把串口对象、模型对象或 ownership 开关塞进日常 open 的公开参数。

Robot 的路径覆盖必须固定映射到同一份配置加载逻辑：

| Robot 参数 | 实际配置使用方 |
|---|---|
| arm_config_path / chassis_config_path / grasp_config_path | 分别作为对应模块的 config_path 来源 |
| servo_config_path | 同时传给夹爪配置、舵机总线配置加载器；后者必须用 config_path=，首位置参数实际是 platform |
| vision_config_path / vision_calibration_path | 分别对应 Vision 的 config_path / calibration_path |
| motor_config_path | arm/chassis 共用的一次 motor 配置快照；集成 Grasp 也使用已有 arm，不另读默认总线 |

各模块 open 与 Robot 都使用该模块同一处真实内部装配：独立 open 负责读配置、创建自有连接，Robot 传入已读快照和共享依赖；不能让 Robot 再逐个调用会重新读文件、打开连接的公开 open。内部测试注入假设备也进入此装配路径，不另建测试专用实现。

独立使用各模块也保持同样的调用形状，以下同样是待实现接口：

```python
from modules.arm import RobotArm
from modules.servo import GripperServo

with RobotArm.open() as arm:
    arm.move_up(pulses=800)

with GripperServo.open() as gripper:
    report = gripper.open_jaws()
```

共享设备的组合使用仍走 Robot.open；统一签名不意味着可以独立打开两个占用同一串口的会话。

## 3. 初始化内部必须真正处理的事情

| 现状 | 必须实现的目标 |
|---|---|
| RobotArm 与 MecanumDrive 分别打开 motor/config.json 的同一个端口 | 同一 Robot 会话只打开一条步进连接，两模块借用它 |
| 两个控制器的 close 当前都会关闭注入串口 | 创建者负责关闭；借用者只停止自身使用并使对象失效，不能切断其他模块的连接 |
| Grasp.open 自建 arm/vision | 集成时明确传入 Robot 已有对象，不取私有 _arm/_source、不重新占用设备 |
| 各模块初始化/使能/收尾分散在 demo/manual | 模块 open/close 承担自身生命周期，Robot 统一装配共享资源；业务不用重复写 initialize/enable/stop/disable/close |
| RobotArm 方向动作已经简单 | 保留其原名和参数，不为凑“统一命名”再包一层转发类 |
| Vision 已返回结构化报告 | 保留既有报告，不另造一个坐标 DTO 或解析 summary 文本 |

资源关系固定为：

```text
Robot 会话（总所有者）
├─ 一条 Emm42 步进连接
│  ├─ arm 使用地址 5/6/7
│  └─ chassis 使用配置中的四轮地址
├─ gripper：独立舵机连接
├─ vision：一个相机和一个模型
└─ 需要抓取时，Grasp 复用同一 arm/vision
```

首批按上层顺序调用；不引入线程池、设备注册框架、自动发现和自动降级。共享串口不等于支持跨线程并发，协议请求不能交错。

同一会话中 motor 配置只读一次；arm/chassis 共用的端口、波特率一致，电机地址不能冲突。所有被选模块的配置先完成校验，再打开第一个设备；开启 arm 的普通脉冲能力不额外要求绝对定位标定。初始化任何一项失败，已取得的资源都要尝试释放。

总关闭时先使借用的抓取会话失效，再按取得资源的逆序逐个调用模块 close，最后关闭共享步进连接。第一项失败不阻断其他项；不自动开闭爪。arm/chassis 的上层 close 内部分别尝试 stop、失能本模块的轴、使对象失效及释放自有资源；Robot 不在它们之前再执行一遍 stop/disable。底盘的 MecanumDrive.close 只负责驱动对象/自有串口的释放，不再重复上层已做的停机。提前关闭的模块再次 close 无动作，共享连接最终只关闭一次。各清理步骤独立尝试；Python 3.8 可用的普通异常链即可，不引入新版 ExceptionGroup。

### 3.1 抓取借用路径

在 `Grasp` 增加 `from_modules(*, arm, vision, config_path=None)` 类方法。它读取并校验现有 eye_in_hand 配置中的 selector / target / jacobian / lift_scale，绑定传入的真实 arm/vision，不打开设备、不重新使能、不读取另一份视觉/机械臂配置。借用会话的 close 只结束本会话，不能 stop/disable/close 所借设备；设备最终收尾归 Robot。

既有独立 `Grasp.open(...)` 仍是有实际用途的设备拥有入口，与 from_modules 复用同一份参数校验、会话装配和动作实现，不复制流程、不增加旧入口转发壳。Robot 在开设备前预校验抓取配置，内部通过 `Grasp._from_modules_settings(...)` 消费同一 config / selector / target / jacobian / lift_scale 快照；公开 from_modules 读好快照后也进入此装配接缝，不在装配后重新读配置覆盖它。`arm=True, vision=True` 不隐含 grasp，不要求 target/Jacobian。

独立 Grasp.close 对自有 arm/vision 逐个调用其 close，由 arm.close 执行自身停机，避免原有 stop_all/disable_all/close 与新生命周期重复。旧 GraspPipeline 的 arm/gripper 也是传入的借用对象，不能在它的 close 中擅自关闭；本地会话失效与资源释放分开，最终关闭由装配者负责。

## 5. 机械臂双坐标的确定契约

### 5.1 同一个夹持点、同一个基座参考

两种输入都定位爪口中心，且都是相对固定基座参考的绝对目标。`base_degrees` 是底座实际角位置，`radial_mm` 是夹持点距旋转轴的水平距离，`height_mm` 与 `z_mm` 是同一高度。沿用当前工程的高度约定：台面为 Z=0，向上为正；XY 原点为基座旋转轴与此参考平面的交点。它不是摄像头光心，也不是“回零后所在位置”。

+X 为标定的底座 0° 方向，+Y 为沿现有 `rotate_cw` 正方向转 90° 后的方向；角度符号沿用 CW 为正。按这个约定使用现有 `atan2(Y, X)`，不另套一个方向相反的默认坐标系。现场标定要验证正角运动与 +Y 一致。

数学关系固定为：`x = r*cos(theta)`、`y = r*sin(theta)`、`z = h`；逆解为 `r = hypot(x,y)`、`theta = degrees(atan2(y,x))`、`h = z`。三角函数中的 theta 使用弧度，接口角度使用度，换算只在纯数学层完成。该模型要求夹持点随伸缩沿径向运动、随升降沿 Z 运动，底座零角方向与夹持点径向一致，须在现场标定中确认。复用现有 kinematics 的数学实现，不在两个动作方法里分别重写。XYZ 只转换目标，之后与圆柱入口进入同一规划和执行。

`x=y=0` 时 XYZ 没有确定底座角度：保留当前角度，再检查 r=0 是否在实测行程内；不得由 atan2(0,0) 隐式产生一次转到 0° 的动作。圆柱入口显式给出的角度仍生效。所有输入拒绝 bool、NaN、无穷值与负半径。

### 5.2 回零建立参考，不在 open 时自动运动

新 RobotArm 实例从位置未知开始。上层显式调用 `home_all(wait=True)`，内部按伸缩→升降→底座顺序回零；开始前使旧位姿失效，三轴调用与等待全部完成后，才按已配置的 `safe_pose` 记录参考。该字段表示**驱动零点姿态处夹持点的实测圆柱坐标**，通常不为全零；同时是现有安全廊道参考，不新增一份重复的 home_pose。

能够建立绝对参考的回零必须在第一条回零帧前校验 homing、safe_pose、三轴行程及其一致性，并核实实际回零方式能回到唯一物理参考。当前 nearest 是电机单圈参考；若某轴允许行程跨越多个电机圈，配置一个参考坐标也不能消除回错圈的问题。检查不能只覆盖底座，还要按导程检查升降、伸缩；缺少判断所需标定就明确拒绝建立绝对参考。不把普通等待或填写坐标当成解决方案，不自动改驱动配置或增加相机兜底。

nearest 的条件比“行程小于一圈”更严格：在实际起点处于已标定行程内的前提下，该行程两端距参考位都必须**严格小于半个电机圈对应的轴位移**。底座一电机圈为 `360 / reduction_ratio` 度，直线轴为 mm_per_motor_rev 毫米；半圈等距而方向未明确时也拒绝。例：40 mm/圈、参考 0、行程 [0,30]，虽不足一圈，从 30 就近回零仍会走到 40 而非 0，必须预检失败。其他回零模式同样需要实际驱动设置与可达固定参考的依据，不能仅因配置名字不同就判为可靠。

当前 Response=None，没有回零成功或到位反馈。文档、返回值与注释只能说明“按已标定前提执行并等待后的推算参考”，不能声称检测到了物理零点。现场必须先验收回零重复性；当前 homing 模式若不满足固定参考前提，实机双坐标功能仍被阻塞。

`home_axis`、`home_all(wait=False)`、`move_axis_to_zero`、`move_all_to_zero` 必须明确影响位姿：单轴与异步操作不建立三轴参考；整臂归位只有在既有参考有效、全部预检与等待完成后才可更新。回零中途失败、停止、失能或关闭立即置未知。不能只在新增 move_to 中跟踪位置，却漏掉这些既有动作。

### 5.3 位姿只归机械臂所有，按真实命令量更新

仅 RobotArm 持有并更新一份圆柱位姿与来源，XYZ 每次由它计算，不另存第二份。位姿数据归 arm 模块，arm 不导入 grasp。来源需区分未知、回零参考、已标定测量与命令推算；“命令推算”仍可连续执行绝对定位，不能误用现有 is_absolute 判断而在第一步后禁止第二步。

所有方向脉冲动作与相对度/毫米动作都走同一位姿更新路径：已有有效参考、对应标定齐全且 wait=True 时，按实际下发的带符号整数脉冲反算增量；发帧前校验对应轴的实际路径与已配置行程。方向原语不自行绕安全廊道，也不改变调用者指定的动作。小于半脉冲而量化为 0 的请求不发帧、不改变位置；不能把用户请求的浮点目标直接写成已到达位置。相对单位方法再调用底层动作时只能累计一次。

当前位置原本未知时，相对动作不能凭空生成绝对位置。缺少换算标定、wait=False、发帧/等待中断或异常会使位置未知；纯输入/配置/全路线预检失败且尚未发运动帧时，保留原有效位置。未知状态下两个绝对入口抛 RuntimeError，零运动帧；不开默认原点、不自动回零、不自动重试。

当前 Grasp 的视觉伺服使用 wait=False 发脉冲并自行等待，本轮不重写其并行动作算法。这些动作必须使 arm.pose 失效，流程返回后不能凭一次 sleep 恢复旧位姿；若上层随后要用绝对坐标，须显式重新建立参考。已标定的旧 pipeline 测量路径可以通过机械臂提供的 `record_measurement(pose)` 写入有效基座夹持点测量；它是对现有观测消费者的迁移，不作为自动恢复策略。测量必须先通过相同的数值、夹持点、行程校验；相机只给方向角时，须与已知连续角位置对应，或在行程内有唯一等价角。未知状态下有多个圈数候选时，拒绝写入，不能用图像方向猜实际圈数。

### 5.4 靶标坐标不能直接写成夹持点坐标

旧 `pipeline.measure_pose()` 把 `observation.marker` 直接写入状态，抓取目标高度又额外加 `marker_to_grasp_mm`。改成夹持点位姿后，这两处必须一起调整，不能只重命名字段。

在现有“靶标与夹持点平面位置相同、靶标在上方”的实测安装关系成立时：`h_grip = h_marker - marker_to_grasp_mm`，XY 不变；抓取高度直接为 `material_height_mm * grip_ratio`，悬停高度再加 clearance。禁止写入位置时未减偏移、生成目标时却继续加偏移，造成重复补偿。safe_pose、height/radial 行程、两种移动返回位置、旧流程的 place_at/park 也必须按同一个夹持点解释。

上述平面重合关系和竖直偏移需有实际标定；若现场不满足，不允许猜横向偏移为零或拿靶标代替夹持点。应报告缺失的安装几何条件，不在此追加通用工具坐标树。机械臂独立使用只依赖自己的夹持点回零与行程标定，不需要读取 grasp 的靶标配置。

视觉 `locate()` 继续返回相机坐标；眼在手上的相机系随机械臂运动，直接把 report.best 的 xyz 传给 arm.move_to 是错误调用。本轮不隐式增加手眼标定或把相机坐标伪装成基座坐标。

### 5.5 路径和限位在第一帧前完整验证

两个绝对入口在动作前要求两根直线轴的 mm_per_motor_rev、底座减速比、三轴 limits、safe_pose 与有效当前位置全部齐全。当前 JSON 中毫米标定、参考位与行程都未填写，所以现状不能直接完成真机双坐标定位；这些要求不扩大到普通脉冲初始化。

沿用现有安全廊道：需转角时，先到安全半径、再到安全高度、再旋转、再到目标半径、最后到目标高度；不转角时，先改半径、再改高度。只用现有相对脉冲串行执行，不增加多轴插补或宣称末端沿 XYZ 直线运动。参考位必须经现场确认适合作为这条廊道；软件行程检查不等于环境避障。

圆柱入口的角度是实际受限角位置，直接计算目标角减当前角，不对机械行程做无条件归一化。XYZ 逆解得到方向角后，在实测角行程内选等价角 theta+360*k，取合法行程内所需转角最小者，同长度时取 CW；无合法候选则失败。实际角位置的连续记录不能被归一化洗掉。

例如限位 [-170°,170°]、当前位置 170°、目标 -170°，不能走穿过限位的 +20°。实际角行程内是 -340°；若对应单段脉冲超过 max_pulses，则整次请求在第一帧前失败。不得自动拆段绕过上限，也不能只验两个端点就宣称路径合法。

完整预检包含：目标和全部中间位姿、当前有效参考、所用标定、速度/加速度、每段整数脉冲、量化后轨迹与最终位置的行程。规划时逐段按量化脉冲推算下一段起点，与实际执行使用同一结果；后段非法时前段也不能先动。执行中发生错误则使位姿未知，停止本次后续段并抛出原始失败。

## 6. 验收标准

以下是交给执行 agent 的完成标准，不以“已经加类和方法”作为验收。

| 场景 | 可验证结果 |
|---|---|
| 上层示例 | 本文全部目标示例可在假设备下直接运行；一条 with 完成装配，每个动作一行，不读私有字段 |
| 管理类一键启闭 | Robot.open_all 与五项全选的 Robot.open 取得相同模块集合并使用同一装配；一次 robot.close 或退出 with 释放全部自有资源；无需分别调用各模块 close |
| 一键开启失败 | 任一模块启动失败时已开启模块均被清理，不返回半就绪 Robot，不跳过失败模块；grasp 不重复创建 arm/vision |
| 统一生命周期 | 六类的 open 均为关键字类方法并返回就绪对象；close 无业务参数且返回 None；closed 与关闭后失败行为一致；三种执行器的停止都用 stop() |
| with 不二次初始化 | 统计配置读取、串口打开、模型加载与使能次数，open + __enter__ 只发生一次；上层不再需要 initialize |
| 上层文件归属 | 五个模块的公开类真实定义均在各自 runtime.py；包根显式导出；旧三个上层文件无转发实现或活动代码引用；导入无循环 |
| 设备与导入 | arm+chassis 只打开一条步进连接；只启用 arm 不导入视觉运行依赖、不读取视觉/抓取配置；import robot 与展示 test.py 菜单零设备副作用 |
| 资源共享 | Grasp 使用与 Robot 相同的 arm/vision；关闭借用会话不影响设备；关闭一个借用步进模块不影响另一个 |
| 故障收尾 | 任一初始化阶段故障都释放已取得资源；清理中途故障仍尝试剩余项；重复 close 无动作；关闭后调用明确失败 |
| 关闭不重复 | 独立模块、独立 Grasp、Robot 集成三条正常关闭路径中，本模块自动停机/失能/物理关闭各执行一次；提前 close 子模块后总关闭不重复；借用者不关物理连接 |
| 构造中途失败 | 假设备在第 2/3 轮驱动构造时失败：自有串口释放，借入串口保留给所有者收尾；初始化未返回对象时也无资源遗失 |
| 配置覆盖 | 自定义路径传给真实模块并只读快照；未选模块的坏配置不阻塞已选模块；不改文件、不猜缺失标定 |
| 回零参考 | open 无运动且 pose=None；显式回零顺序为伸缩→升降→底座；成功等待后采用配置中非零夹持点参考；中断后未知 |
| 回零唯一性 | 底座或任一直线轴单圈参考有多圈歧义时，拒绝建立绝对参考；不因为填写 safe_pose 就放行 |
| nearest 半圈边界 | 假配置 40 mm/圈、参考 0、行程 [0,30] 在第一条回零帧前失败；恰好半圈也拒绝；三轴分别覆盖 |
| 两种坐标 | 在同一初始状态下，圆柱 (90°,100,60) 与 XYZ (0,100,60) 生成相同规划、帧与推算位置；覆盖四象限及角度符号 |
| 连续混用 | 圆柱→XYZ→方向脉冲(wait=True)→XYZ 使用同一更新后位置；无重复累加、无独立 XYZ 缓存 |
| 夹持点 | 测试给定靶标高度 72、实测竖直偏移 12 时，写入夹持点高度 60；抓取高度不再额外加 12；独立 arm 不读取该抓取配置 |
| 量化 | 在假配置中用不足半脉冲的目标验证零发帧、位置不变；多段位置按实际整数脉冲累计，不按请求目标直接赋值 |
| 全程预检 | 未回零、缺标定、缺 limits、负半径、非有限值、末段越界/超脉冲时整次零运动帧；纯预检失败不破坏原有效位置 |
| 角度限制 | [-170°,170°] 下的 170→-170 不走非法 +20°；允许的实际路线也要通过每段脉冲上限；不自动分段 |
| 轴心目标 | XYZ(0,0,z) 保留当前角度；r=0 越界则零发帧失败；不出现隐式转 0° |
| 位姿失效 | stop/失能/close、单轴回零、wait=False、发帧后异常和当前视觉伺服后，不能沿用旧位置继续绝对移动 |
| 调用者迁移 | main.py 与至少一个对应手动入口使用 Robot；旧 pipeline 不自建第二份位姿或路径规划，观测先换到同一夹持点 |

数值用例只使用假配置，不写回现场 JSON。实现验证可复用现有 unittest 与假串口，不新增依赖；报告实际通过的测试范围，并把尚未做的现场毫米标定、固定参考回零与定位误差验收单独列出。
