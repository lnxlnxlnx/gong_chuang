# 转盘控制说明

> 适用对象：分度转盘（幻尔总线舵机，ID 2），三个**物料放取工位**。
>
> 本文只定义已确认的通讯事实、配置位置和代码边界。`0 / 500 / 1000` 是现场给出的三个工位
> 位置，**尚未在真机上逐点核对**——装机后必须用菜单 20 走一遍确认，见第 9 节。

## 1. 硬件与接线

转盘和夹爪挂的是**同一条总线舵机总线**，不是机械臂/底盘那条 Emm42 步进总线：

| 项目 | 值 |
|---|---|
| 协议 | 幻尔总线舵机半双工协议，帧头 `55 55`，多字节**小端** |
| 波特率 | 115200 bps |
| 物理层 | 5 V 上拉的单线半双工 UART |
| 转盘 ID | **2** |
| 夹爪 ID | 1（同一总线上的另一台） |

接线必须用**总线舵机专用 USB 转接板**，或具备半双工收发切换 + 3.3 V/5 V 电平转换的模块；
普通 USB-TTL 的 `TX`/`RX` 不能直接并接在信号线上。

串口不是转盘自己的参数：端口取 `modules/servo/config.json` 的 `windows.port` / `jetson.port`
（舵机总线唯一来源，与夹爪共用），转盘只声明自己的 `servo_id`。

**两个舵机只靠 ID 区分。** 撞号不会报通讯错误，只会让转盘指令去开合夹爪（或反过来），
现场看到的只是"动作不对"。所以 `load_turntable_config()` 会拿 `gripper.servo_id` 对一遍，
撞号时在打开串口之前就报错。

## 2. 位置量程与工位

舵机位置 `0..1000` 对应输出轴 `0..240°`，步距 `0.24°`。转盘**直连、无减速器**，
所以这个角度就是转盘的名义转角：

| 工位 | 位置 | 名义角度 | 说明 |
|---|---:|---:|---|
| `home` | 0 | 0° | 回零位；`go_home()` 走到这里 |
| `station_2` | 500 | 120° | 二号物料放取位 |
| `station_3` | 1000 | 240° | 三号物料放取位 |

三个工位正好相隔 120°，这是三工位分度盘的正常间距——**但它只是"看起来对"，
不等于已经标定过**。真实工位位置由舵机安装角度和转盘机械零点决定，必须实测。

工位名和位置都写在 `modules/servo/config.json` 的 `turntable.stations` 里，代码不写死：

```json
"turntable": {
  "servo_id": 2,
  "duration_ms": 1500,
  "stations": { "home": 0, "station_2": 500, "station_3": 1000 }
}
```

`stations` 必须有一个叫 `home` 的工位，否则 `go_home()` 没有确定的目标——载入配置时直接拒绝。

## 3. 为什么没有"触发回零"这个方法

机械臂的 Emm42 步进驱动器需要 `0x9A` **触发回零**来建立绝对参考：它的位置计数器掉电即
失效，"回零"是一个**动作**。

**总线舵机不是这样**：它内部一直是绝对位置（`0x1C`/`POS_READ` 读回来的就是当前真实角度），
上电就知道自己在哪，没有"回零"这个动作可以触发。所以转盘的"回零"就是**走到 `home` 工位**
这**一个**动作：

- `go_home()` 是它的语义入口；
- `go_to(position)` 是同一个动作的通用形式。

真要把某个姿态定义成新的零点，那是舵机的**偏差标定**（指令 17/18，掉电保存），属于装机时
做一次的事，本层**刻意不封装**——它会把"转盘现在认为哪是 0"永久改掉，不适合在流程里随手
调用。要改就用舵机调试软件或串口助手，改完把新的工位位置回填到 `stations`。

同理，指令 20/21（角度限制）也没有封装：它是一道**舵机内部**的软限位，装错会让舵机
直接拒绝走到某个工位，排查起来比在配置里写清楚工位难得多。

## 4. 代码结构

依赖方向只能从上到下：

```text
modules/servo/test/manual/turntable.py     交互式真机测试（菜单 20）
                 |
                 +--> drive/turntable.py        工位分度、回零、读回到位判据
                 |          |
                 |          +--> drive/bus_servo.py  半双工协议帧、读写指令
                 |          |
                 |          +--> config.py          turntable 段的读取与校验
                 |
                 +--> modules/servo/config.json     唯一可编辑的转盘参数
```

- `modules.servo.drive.turntable.TurntableServo`：把"走到几号工位"映射成绝对位置命令，
  统一校验工位名、等待转动、**读回核对**到位。
- `modules.servo.config.load_turntable_config()`：把 JSON 转成已校验的 `TurntableConfig`，
  是配置文件和代码之间唯一的适配点。
- `modules.servo.test.manual.turntable`：只控制人工确认、执行顺序和清理；不保存运动参数。

`TurntableServo` 和 `modules.servo.drive.gripper.GripperServo` 是同一层的兄弟：共用
`BusServo`，各自补上自己的语义（一个管爪口开合，一个管工位分度）。

## 5. API

| 物理动作 | API | 返回值 |
|---|---|---|
| **回零**（走到 `home` 工位） | `go_home(*, duration_ms=None, wait=True)` | `TurntableReport` |
| 转到具名工位 | `go_to_station(name, *, duration_ms=None, wait=True)` | `TurntableReport` |
| 走到任意位置（**标定用**） | `go_to(position, *, duration_ms=None, wait=True)` | `TurntableReport` |
| 读当前位置 | `read_position()` | `int` |
| 是否停在工位上 | `at_station(name, *, tolerance=None)` / `is_at(position, ...)` | `bool` |
| 生命周期 | `initialize()` / `close()` / `stop()` / `set_torque(bool)` | — |

参数含义：

- `duration_ms`：这条命令**用多少毫秒**走到目标（协议范围 0..30000）。不传就用配置里的
  `turntable.duration_ms`。给得太小舵机会按自己的最高速冲过去，带料时容易甩。
- `wait`：`True`（默认）等到转动时长走完并**读回核对**再返回；`False` 只发命令。

`go_to()` 是**原始**入口，它不检查目标是不是某个已配置工位——标定时要试的正是"还没成为
工位"的位置。流程代码请用 `go_to_station()`，它在发帧之前就把写错的工位名挡下来。

## 6. 到位判据用的是读回值，不是估算

舵机的 `POS_READ` 会回**当前真实位置**，所以 `go_to_station()` 等完转动时长后读回来核对，
`TurntableReport.reached` 是一个**测量结论**：

| 字段 | 含义 |
|---|---|
| `command` | 工位名；`go_to()` 直接给位置时是 `"set"` |
| `target` / `position` | 命令位置 / 读回位置 |
| `reached` | 读回值与目标相差不超过 30 个位置单位（7.2°） |
| `error` | 读回位置减目标位置 |
| `degrees` | 读回位置对应的名义转角 |

这和机械臂不同：Emm42 的位置命令没有到位回包，那边只能按说明书的曲线加减速公式估算耗时。
转盘挡住、被料卡住或丢步时读回值会明显偏离目标，`reached` 为 `False`，`summary()` 会打印
"未到位（差 ±N）"——**这是信号，不是异常**，工位之间差 120°，差 100 个单位说明它根本没转到。

`wait=False` 时不等待，读回的是"命令前"的位置，所以 `reached` 一律为 `False`，如实标注而不是
假装知道。

## 7. 改参数

日常参数只改 `modules/servo/config.json` 的 `turntable` 段，不改 Python：

| 参数 | 含义 | 校验 |
|---|---|---|
| `turntable.servo_id` | 转盘舵机在总线上的 ID | `1..253`，且不能等于 `gripper.servo_id` |
| `turntable.duration_ms` | 默认转动时长 | `1..30000` |
| `turntable.stations` | 工位名 → 位置 | 至少 2 个；名字非空；位置 `0..1000`；**必须有一个 `home`**；两个工位不能停在同一个位置 |

「两个工位停在同一个位置」这一条是防抄错：分度盘上那等于丢了一个工位，而舵机不会有任何
异常表现。

配置无效时，程序会在**打开串口和发送任何命令之前**退出。

## 8. 真机测试

在项目根目录运行统一测试菜单并选择 **20. 转盘测试**：

```powershell
python test.py
```

脚本先读一次当前位置，然后按 **`home` → 其余工位（配置文件顺序）** 逐个询问，每个工位都要
**单独确认**才会动。**回零排在第一位不是装饰**：三工位转盘上电时的朝向我们并不知道，
先回零把"现在在哪个工位"定下来，后面两个工位才是从已知位置出发的。

```
转盘舵机 2 @ COM14 115200 bps
转盘舵机 2 当前位置：0
转盘将转到工位 home（位置 0，约 0.0°，耗时 1500 毫秒）。确认转盘有活动空间、机械臂已让开之后按回车执行，输入 q 结束，其他输入跳过：
```

三种输入各有各的用途（和机械臂测试是同一套手感）：

| 输入 | 行为 |
|---|---|
| **回车** | 执行这个工位 |
| `q` | 结束剩下的动作，直接进入收尾 |
| 其他任意输入 | 只跳过这一个工位，后面的继续问 |

回车就是"执行"而不是"跳过"——真机调试要连着走好几个工位，每次都敲一遍确认词是纯粹的负担；
`q` 和"其他输入"分开保留，是为了在"手已经放在回车上了"和"发现不对想停下来"之间还留得住区别。

每次动作后打印读回结果：

```
转盘home：目标 0（0.0°），读回 0（0.0°），到位
转盘station_2：目标 500（120.0°），读回 497（119.3°），到位
```

接线不确定时可以临时换端口：

```powershell
python -m modules.servo.test.manual.turntable --port COM7
```

脚本用比生产路径更宽的读回超时（0.5 s），这样接触不良会报"没回包"，而不是被误当成
"舵机不动"。正常结束、异常和 `Ctrl+C` 都会停止舵机并关闭串口。

## 9. 装机后必须确认的事

以下数据在代码里都有默认值，但**默认值不等于标定值**：

| # | 要确认的 | 怎么确认 | 错了会怎样 |
|---|---|---|---|
| 1 | 转盘舵机 ID 真的是 2 | 读 ID（菜单 12，或 `SERVO_ID_READ`） | 指令发给夹爪，爪子开合而转盘不动 |
| 2 | 三个工位的**真实位置** | 用菜单 20 的 `go_to()` 逐点试，或舵机调试软件手动拖到工位后读回 | 放取位置整体偏移；三工位间距不等会越转越偏 |
| 3 | `duration_ms` 带料够不够稳 | 装上物料跑菜单 20，看到位读回和有无甩料 | 太短会冲、会甩料；太长节拍慢 |
| 4 | 断电位姿与上电后的 `home` 是否一致 | 断电前停在 `home`，上电后读位置 | 舵机绝对位置由内部编码器保持，但**舵机与转盘的机械连接打滑**会让它整体偏掉 |
| 5 | 转盘与机械臂的**互锁** | —（本层不做） | 转盘转动会撞到停在料盘上方的机械臂 |

第 5 条是**刻意留给上层**的：本层只负责"把转盘转到某个工位"，它不知道机械臂在哪。转盘转动
前必须由调用方保证机械臂已让开——和机械臂那边"伸出状态下不许转底座"是同一条规矩。

## 10. 自测

不需要硬件，用一个假舵机验证工位分度、回零、读回到位判据、容差边界与异常路径：

```powershell
python -m modules.servo.drive.turntable
```

离线单测（不打开串口）：

```powershell
python -m unittest modules.servo.test.unit.test_turntable modules.servo.test.unit.test_turntable_config modules.servo.test.unit.test_turntable_manual -v
```
