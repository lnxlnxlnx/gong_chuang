# 抓取坐标链路：从摄像头像素到机械臂脉冲

本文是「摄像头识别 + 机械臂抓取」的完整说明，也是各标定脚本与配置字段的出处。
代码里的注释凡是提到"见 modules/grasp/docs/抓取坐标链路.md"的，指的都是这里。

---

## 0. 先确认相机装在哪：两套做法互不通用

后面第 1–2 节描述的是**相机固定在天上**（eye-to-hand）的链路：相机不动，所以
"物块在相机系的坐标"能换算成一个固定的世界位置，再用一次平面标定接到基座坐标上。

**本机的相机装在机械臂上、跟着爪子一起动**（eye-in-hand）。这时那套换算**不成立**——
相机自己在动，"物块在相机系的坐标"里混着机械臂的运动，换算不出固定位置。
本机要用的做法在文末 **第 10 节**，代码在 `modules/grasp/drive/eye_in_hand.py`。

| | 相机固定（第 1–2 节） | **相机在臂上（本机，第 10 节）** |
|---|---|---|
| 定位原理 | 相机系 → 基座平面 → (θ, r, h) | 把观测量**伺服到定值** |
| 要标定 | 像素焦距、平面标定、`mm_per_motor_rev`、行程 | 目标读数 `(tx, ty)`、2×2 雅可比 |
| 爪子怎么被看到 | 爪上必须贴一个靶标 | **不需要**——相机与爪子刚性同体 |
| 驱动量 | 毫米（要机器常数） | **脉冲**（一个常数都不要） |

判断方法很简单：命令机械臂平移一段，看镜头报的 `xyz` 跟不跟着变。
跟着变 ⇒ 相机在臂上。

## 1. 系统形态

> 本节及其后到第 9 节描述的都是**相机固定**的形态。本机不是这种，见第 0 节。

| 部件 | 现状 | 对方案的影响 |
|---|---|---|
| 相机 | **固定俯视**（拍物料顶面），不装在臂上 | 是 eye-to-hand，只要一次平面标定，不需要 6D 手眼标定 |
| 机械臂 | 三轴**圆柱坐标**：底座旋转 θ / 升降 h / 径向伸缩 r | 逆解只有两行三角函数 |
| 夹爪 | 舵机驱动，**侧向夹取**，无腕部旋转 | 爪口朝向 = θ；夹持高度依赖物料高度 |

### 坐标系约定

- **相机系**：原点在镜头光心，`x` 向画面右、`y` 向画面下、`z` 沿光轴向前（俯视时向下）。
  由 `modules/vision/drive/pinhole.py` 给出，单位毫米。
- **基座系**：原点在底座旋转轴，`X`/`Y` 是水平面，`Z` 向上。
- **圆柱关节量**：`base_degrees`（底座转角，CW 为正）、`radial_mm`（到旋转轴的水平距离）、
  `height_mm`（**离台面**的高度）。由 `modules/arm/drive/kinematics.py` 定义。

## 2. 五级坐标链

| 级 | 变换 | 谁负责 | 依赖的标定 |
|---|---|---|---|
| 0 | 像素 → 相机系毫米 | `vision/drive/pinhole.py` | 像素焦距 `focal_px` |
| 1 | 相机系毫米 → 基座平面 (X, Y) | `vision/drive/calibration.py` | 平面标定（实验 A） |
| 2 | (X, Y) + 高度 → (θ, r, h) | `arm/drive/kinematics.py` | 无 |
| 3 | 夹持高度 | `kinematics.marker_height_for_grasp` | `grip_ratio`、`marker_to_grasp_mm` |
| 4 | 物理量 → 脉冲 | `arm/drive/kinematics.py` | 底座 `reduction_ratio`；直线轴 `mm_per_motor_rev` |

### 第 0 级

```
z_mm = focal_px × 直径 / (2 × 像素半径)
x_mm = (u − 画面宽/2) × z_mm / focal_px
y_mm = (v − 画面高/2) × z_mm / focal_px
```

**光轴竖直向下时 `z` 就是竖直距离**，因此 `x_mm/y_mm` 是真正的水平毫米坐标，与该点高度无关。
这一条是整个方案的基础：不同高度的靶标和物料仍然落在同一个水平平面里。

相机一旦倾斜，水平坐标会带上与高度相关的偏置。标定前请确认镜头确实接近竖直向下。

### 第 1 级

相机水平面与基座平面之间只差一个刚体变换：

```
X_arm = R(rotation_degrees) · (p_cam − center)
```

- `center`：底座旋转轴在相机水平面上的投影，对应 `p_cam` 里 `r = 0` 的点；
- `rotation_degrees`：θ 零点偏置。

**这里刻意没有缩放参数。** 尺度由像素焦距承担；再放一个缩放会和焦距互相吞掉，
两个数永远无法同时确定。焦距不准就重标焦距，不要用缩放去凑。

> **方向约定（很重要）**：标定时记录的 `base_degrees` 必须就是用
> `RobotArm.move_base_degrees` 或 `rotate_cw` **命令出来的累计角度**（CW 为正）。
> 只有这样，拟合出的 θ 才和命令同向，抓取流程里 `move_base_degrees(Δθ)` 的方向才是对的。

### 第 2 级

```
base_degrees = atan2(Y, X)        radial_mm = hypot(X, Y)
```

`base_degrees` 落在 `(-180, 180]`，与 `atan2` 同域。**预测位姿也要归一到这个区间**
（`kinematics.normalize_degrees`），否则"从 170° 再转 20°"会记成 190°，虽然物理上就是
-170°，却通不过 ±180 的行程检查。

### 第 3 级

侧向夹取的夹持高度跟着物料高度走：

```
夹持点高度 = 物料高度 × grip_ratio        # 0 贴台面、0.5 半高、1 顶面
靶标高度   = 夹持点高度 + marker_to_grasp_mm
```

`marker_to_grasp_mm` 是靶标相对**实际夹持点**的竖直偏移，靶标在夹持点上方时为正。
这是单目测距真正被用到的地方——它不只为 XY 服务。

### 第 4 级

```
脉冲 = 角度 × PPR × reduction_ratio / 360          # 底座
脉冲 = 位移 × PPR / mm_per_motor_rev               # 升降 / 伸缩
```

`mm_per_motor_rev` 就是丝杠导程 `L` 与减速比 `g` 的**商**。文献里要求分别给出 `L` 和 `g`，
但公式里永远只出现 `L / g`，所以标定这个商即可，不必拆机量导程。

`PPR` = 每电机圈脉冲数（16 细分、1.8° 电机时为 3200）。

## 3. 代码分层

依赖方向只能从上到下，纯计算层不碰串口、不碰 cv2：

```
modules/grasp/drive/pipeline.py        动作编排（只认 CylindricalPose + 几个 Protocol）
        |
        +--> modules/grasp/drive/arm_state.py     位姿与夹爪状态的唯一真相源（位姿 + 来源）
        |
        +--> modules/grasp/drive/perception.py    一帧 → 两个圆柱位姿（视觉与机械臂的唯一接缝）
        |          |
        |          +--> modules/vision/drive/cell_targets.py   同帧区分靶标与物料（唯一碰 cv2 的地方）
        |          +--> modules/vision/drive/pinhole.py        纯针孔模型
        |          +--> modules/vision/drive/calibration.py    纯平面标定数学
        |          +--> modules/arm/drive/kinematics.py        纯圆柱运动学
        |
        +--> modules/arm/drive/robot_arm.py      三轴动作（脉冲制 + 单位制两组 API）+ 回零
        +--> modules/servo/drive/gripper.py      夹爪开合与读回
```

`arm_state.py` 刻意**不做成模块级全局**：全局可变状态在测试里没法隔离，也没法在一个进程里
管两套硬件。这里是"唯一所有者 + 显式注入"——状态只活在一个 `ArmState` 实例里，
`GraspPipeline` 默认自己建一个，要跨模块共享就把它传进去。

配置分成四份，各自只放一类东西：

| 文件 | 性质 | 内容 |
|---|---|---|
| `modules/arm/config.json` | 手改 + 标定写入 | 驱动器地址、传动常数、回零模式、行程范围、安全位 |
| `modules/vision/config.json` | 手改 | 摄像头编号、两类目标的直径与颜色 |
| `modules/vision/calibration.json` | **标定产物** | 像素焦距、镜头到台面深度、平面标定结果 |
| `modules/grasp/config.json` | 手改 | 策略参数：余量、夹持比例、闭环次数与容差 |

**机器常数不进抓取策略文件**：换一台机器只要重标，不用改策略。

## 4. 位姿从哪来：回零还是相机

机械臂只有相对位置模式，"上电后我在哪"必须靠一个**绝对参考**确定。有两条路：

| 参考 | 怎么来 | 强在哪 | 弱在哪 |
|---|---|---|---|
| **回零** | `0x9A` 触发，驱动器走到存的零点 | 快、完全不依赖靶标可见 | 单圈模式可能落到**错误的圈**，而驱动器不报错 |
| **相机** | 测爪上靶标，换算成圆柱位姿 | 不需要额外硬件；能发现上面那种情况 | 靶标必须在视野里；受标定残差限制 |

**库只提供原语，编排由 main.py 决定。** 回零、归位、什么时候用哪条路，都是调用方的事：

```python
from modules.arm.drive.robot_arm import RobotArm
from modules.grasp.drive.arm_state import ArmState

state = ArmState()
arm = RobotArm(port, config=load_arm_config()).initialize()
arm.enable_all()

arm.home_all()              # 上电：三轴各自回到零点（零点设在安全姿态上）
state.record_home(safe_pose)   # 把绝对参考记进共享状态

try:
    ...                     # 干活；GraspPipeline(state=state) 会往里写
finally:
    arm.move_all_to_zero()  # 归位：绝对模式回 0，下次上电还能正常就近回零
    arm.stop_all(); arm.disable_all(); arm.close()
```

`ArmState` 是**跨模块共享**的：电机和舵机在别处也会被驱动，所以状态只该有一个所有者，
谁要用谁拿到同一个实例。它只记事实（位姿 + 来源 + 夹爪读回），**不做判断**。

### 归位靠绝对模式，不需要累加反向位移

回零之后驱动器的位置计数器就在 0，所以"归位"是一条**绝对模式**命令回 0
（`RobotArm.move_all_to_zero()`），不必在上位机记"我走了多少再走回去"。

> 前提是计数器有效，也就是**必须先回过零**。掉电后计数器就没了，再次上电要重新回零。

绝对模式不知道当前位置，所以耗时估不出来：`move_axis_to_zero` 的 `wait=True` 等的是按
**行程跨度**算出的最坏情况（一定不会半路提前返回）；行程没标定时拒绝 `wait=True`，
宁可让你传 `wait=False` 自己等，也不假装知道什么时候到位。

`Emm42Driver` 原先在绝对模式下也拒绝 0 脉冲（那是从相对模式抄过来的检查），
已修正：**相对模式仍然拒绝 0，绝对模式允许**——否则"回原点"这条命令根本发不出去。

### 回零的两个前提

**1. 零点可以设在任意姿态，所以要设在安全姿态上。**

手册 7.1：单圈零点用驱动器菜单 `O_Set → Set O`（或 `0x93` 命令）在**任意姿态**设定，
所以"回零"的语义是"回到你指定的那个姿态"。把三个轴的零点都设在安全姿态上，
回零结束时机械臂正好停在 `safe_pose`，不必再额外走一段。

> 注意 `0x93`（设单圈零点，写进驱动器）和 `0x0A`（清当前位置计数，掉电即失效）是两回事，别混。

**2. 单圈回零要求行程在一个电机圈以内。**

单圈零点建立在那颗**单圈**绝对编码器上，一圈只有一个读数。所以轴在断电瞬间必须距零点不到
**半个电机圈**，就近回零才会落到正确的物理位置。

```
底座 g=5 → 一个电机圈 = 3200 脉冲 = 输出 72°
```

行程一旦超过这个跨度（例如现有的 `max_pulses=5000` = 输出 112.5°），同一个零点就对应不止
一个物理位置。三种应对：

| 做法 | 代价 |
|---|---|
| 把行程压进一个电机圈（底座 ±36°，用 `limits.base_degrees` 强制） | 工作区极窄，通常不够用 |
| 改用**多圈 + 限位开关**回零（模式 3） | 要接一个限位开关到驱动器 IO（手册 7.3 有接线图） |
| **每次断电前停在零点附近**（用完归位） | 依赖操作纪律；意外断电或手动拨动就会失效 |

`ArmConfig.homing_warnings()` 会在打开串口之前把不可靠的配置组合列出来。

### 一个驱动器看不见的失效——需要你自己决定怎么兜

**回零落到错误的圈时，驱动器给不出任何信号**：编码器只有一圈读数，`0x36` 读回来
两种情况都是 0。

第三种做法（用完归位）在正常流程下是可靠的，因为断电时轴就在零点附近。它唯一漏掉的是
**意外断电**（急停、拔电、崩溃）——那时机械臂停在半路，下次就近回零可能落到错误的圈上。

不想要任何"复杂判断逻辑"也能兜住，就是拿现成的两个值比一下：

```python
parked = safe_pose                                  # 期望：回零后应该在这
measured = pipeline.measure_pose()                  # 相机实测（靶标要看得见）
if planar_error_mm(measured, parked) > 容差:
    sys.exit("回零落点不对，别继续")
```

**要不要这一行、放在哪、判不判，由调用方决定。** 库里没有自动做这件事的地方。

### 到位回包（建议开启）

手册 8.1：把驱动器菜单 `Response` 设成 `Reached` 或 `Both`，位置模式到位后会返回
`地址 + FD + 9F + 6B`。实现 `0x9F` 解析后，`wait` 就不必再靠耗时估算——
这**对回零和归位尤其重要**，因为这两件事的耗时都不确定，`estimate_move_seconds` 估不准。

## 5. 标定实验

每个实验都能单独验收，按顺序做。全程用一块**装在爪顶、朝上、已知直径的圆片靶标**
（例如白色 20 mm 圆片），检测复用 `modules/vision/drive/hough_lock.py`。

### 实验 A0｜确认底座减速比（2 分钟，先做）

底座贴一个标记，累计命令 **16000 脉冲**（= PPR × 5，可分成 4 次 4000）：

- 回到原位 → `reduction_ratio = 5` 成立（当前配置值）；
- 只转了 300°（差 60°）→ 实际是 `g = 6`，把 `axes.base.reduction_ratio` 改成 6。

> 当前 `config.json` 用 5。在这个前提下：输出轴一圈 = **16000 脉冲**，1000 脉冲 = **22.5°**，
> `motion.max_pulses = 5000` = 输出 **112.5°**。旧的 `modules/arm/docs/机械臂Emm42三轴控制说明.md`
> 里按 g=6 算的 18.75° 作废。

### 实验 A｜基座轴像点 + θ 零点（= 平面标定）

1. 靶标装在爪顶，固定伸缩量与升降高度；
2. 底座每 1000 脉冲走一步，覆盖尽量大的角度范围（涉及半径变化更好），
   每步记下**靶标在相机水平面的位置**与**当时命令的累计角度**；
3. 拟合：

```python
from modules.vision import CalibrationSample, fit_plane_calibration

fitted = fit_plane_calibration(samples)
print(fitted.summary())          # 基座轴像点、θ 零点、残差 RMS
```

机械臂只有相对位置模式，命令的径向含一个未知起点偏移，拟合会把它一起解掉，
所以**不需要**先把机械臂开到某个人为的零点。

产出写入 `modules/vision/calibration.json` 的 `plane`。**残差 RMS 超过 5 mm 就别继续了**，
抓取精度会被它直接拖住。

### 实验 A′｜在真实安装高度重标焦距

`focal_px = 已知距离(mm) × 圆片像素直径 / 真实直径`，多次取平均，写入 `calibration.json`
的 `focal_px`。

> 仓库里的 1012 px 是从一张"约 145 mm"的粗测照片反推的，距离估偏多少焦距就等比偏多少。
> **相机必须抬高**：水平 FOV ≈ 64.6°，可见宽度 ≈ 1.265 × 相机高度。145 mm 高度下只有
> 183 mm 宽，装不下机械臂的扫描范围；要让半径 150 mm 的轨迹全部入画，相机约需
> **250–300 mm** 高（此时 1 px ≈ 0.3 mm，30 mm 圆面仍有约 100 px，霍夫仍可靠）。

### 实验 B｜伸缩轴 mm/电机圈

固定底座与升降，伸缩走 `0 → 2000 → 4000` 脉冲，每步量靶标到基座像点的距离变化：

```
mm_per_motor_rev = Δr_mm × PPR / Δpulses
```

写入 `axes.extension.mm_per_motor_rev`。

### 实验 C｜升降轴 mm/电机圈

固定底座与伸缩，升降走 `0 → 2000 → 4000`。因为光轴竖直，**升降 ΔH 就等于相机深度变化**：

```
ΔH = focal_px × D / d_前 − focal_px × D / d_后      # D = 靶标真实直径
mm_per_motor_rev = ΔH × PPR / Δpulses
```

写入 `axes.lift.mm_per_motor_rev`。

### 实验 D｜镜头到台面的深度

把靶标平放在台面上，量出 `z_mm`，写入 `calibration.json` 的 `table_depth_mm`。
物料高度 = `table_depth_mm − 物料顶面 z_mm`。

### 实验 E｜夹爪与 TCP

1. 真实物料放台面，点动到爪口刚好夹住，量出靶标到夹持点的竖直距离 → `marker_to_grasp_mm`；
2. 标定真实的 `open_position` / `closed_position`（当前 300/500 是占位值）；
3. 量爪口开度范围，确认能张到物料外径以上（照片里的物料外圈约 39 mm）。

### 实验 F｜行程范围与安全位

把三个轴分别开到两端，记下 `limits` 的三个区间；把"缩回 + 抬升"的那个姿态记为
`safe_pose`。**转角度前机械臂会先回到这个姿态**，它必须是一个真实的、无碰撞的中间位姿。

> `limits` 为空等于这几个轴**没有软件行程保护**。程序不会替你假检查。

### 实验 G｜重复精度与背隙

1. 同一个目标位姿走 10 次，用相机量散布 → 这就是系统的重复定位精度；
2. 正走 / 反走到同一点，量差值 → 背隙。

闭环用 `correction.gain`（默认 0.8）逐次收敛，背隙靠"每次都重新测量"吃掉；
不要试图用加大 gain 来提速，超过 1 会振荡。

### 实验 H｜回零零点（用回零方案时必做）

1. 手动/点动把机械臂摆到实验 F 定下的 `safe_pose`（缩回 + 抬升 + 底座朝安全方向）；
2. 三个轴分别用驱动器菜单 `O_Set → Set O`（或 `0x93` 命令）把**当前姿态设成单圈零点**；
   这一步决定了"回零结束时机械臂在哪"；
3. 在 `modules/arm/config.json` 的 `homing.mode` 里填回零模式，
   然后跑 `--home-only` 验收：

```powershell
python -m modules.grasp.test.manual.grasp --home-only
```

预期：三个轴按 **伸缩 → 升降 → 底座** 的顺序各自回零，停在 `safe_pose`。
再用 `--observe-only` 看一次相机测出的位姿，和你标定的 `safe_pose` 对一下。

> **必须断电重启后再跑一遍**：单圈回零的多义性只在"断电时轴停在别处"时才暴露。
> 手动把底座转过半圈、断电、上电、再跑一次——如果相机核对报"对不上"，
> 说明你确实需要限位开关，而不是靠操作纪律。

### 实验 I｜到位回包（可选，但回零时很值）

把驱动器菜单 `Response` 从 `None` 改成 `Reached` 或 `Both`，位置模式到位后会回
`地址 + FD + 9F + 6B`。实现这个解析之后，`wait` 就不必再等一个保守时长——
回零耗时不确定，这一条对它收益最大。改之前先确认新回包不会和现有的 ACK 校验打架
（`modules/arm/docs/机械臂Emm42三轴控制说明.md` §3 已经记了这个坑）。

## 6. 安全约定

编排层（`modules/grasp/drive/pipeline.py`）强制以下几条，不要绕过：

1. **大角度重定位前必须先缩回抬升。** `_command` 发现目标角度不同，就先经 `safe_pose`
   走一遍"缩回到安全半径 → 抬到安全高度 → 转角度 → 再伸出去"。廊道上的每个中间位姿
   都是已知量，不依赖测量。
   `_visual_align` 的小角度修正可以就地转（爪子本就悬在物料上方几十毫米）。
2. **最短转角。** 170° 到 -170° 走 20°，不绕 340°。
3. **可达性检查在发帧之前。** 越界抛 `GraspError`，不发任何动作。
4. **闭环不收敛就不下降。** 迭代用尽仍未进容差时报错——此时下降多半会抓空。
5. **任何失败路径都收尾**：`stop_all` + `disable_all`。**刻意不张开夹爪**——
   中途失败时松开爪子会把已经抓住的东西掉下去。
6. **下降段是盲走**：爪子压上去会遮住物料，所以微调必须在下降之前收敛完。

## 8. 精度与验收

| 指标 | 目标 | 怎么量 |
|---|---|---|
| 平面标定残差 RMS | ≤ 3 mm | `fit_plane_calibration(...).summary()` |
| 重复定位散布 | ≤ 3 mm | 实验 G，同一点走 10 次 |
| 末端到点误差 | ≤ 5 mm | 相机给坐标，臂走过去，反测偏差 |
| 闭环收敛 | ≤ 2 次迭代 | `PickResult.correction_steps` |
| 抓取结果 | `held_something` 为真 | 夹紧时读回值没到闭合位 |

**夹爪的读回值是白送的抓取检测**：命令走到夹紧位置、读回却没到，说明爪口之间有别的东西。
空夹时爪子会一路走到闭合位，此时 `held_something` 为假。

## 9. 已知限制

- **单目 z 由圆面直径反推**，物料倾斜会把圆变成椭圆，同时污染 `x`/`y`/`z` 与物料高度。
  抓取前请把物料放平；`MaterialLocator` / `CellTargetDetector` 都假设圆面近似正对光轴。
- **相机倾斜**会让水平坐标带上与高度相关的偏置。光轴必须接近竖直。
- **相机被遮挡**时闭环失去反馈：物料被爪子压住的那一段是盲走；回零之后整轮都可以不看靶标，
  完全没回零时靶标被挡住就会直接报错。
- **没有堵转检测**：5/6/7 号驱动器是 `Response=None`，`wait` 只是耗时估算。撞到东西软件
  不知道，位姿估计会静默失真。`ArmState` 只如实把这种位姿标成 `dead_reckoned`，
  **不做任何自动纠正**——什么时候重新对账由调用方决定。
  开了到位回包并能读堵转标志才算真正解决。
- **回零不是绝对保险**：单圈回零可能落到错误的圈，而驱动器给不出任何信号（`0x36` 读回来
  一样是 0），只能靠外部观测发现。依赖"每次用完归位、每次断电前停在零点附近"是一条
  操作纪律，不是硬保证；意外断电就会失效。
- **还没接底盘**：物料落在 `r_max` 之外时本流程只会报错。要够远的目标得先让麦轮底盘靠过去。
- **夹爪开合位置仍是占位值**，实验 E 必须做。

## 10. 相机装在臂上时（本机在用）

代码：`modules/grasp/drive/eye_in_hand.py`，真机入口 `modules/grasp/test/manual/align_xy.py`（菜单 21）。

### 10.1 为什么整套换算换掉了

相机随爪子一起动，所以"物块在相机系的坐标"里混着机械臂自己的运动，换不出固定世界位置。
但刚性同体带来一个更省事的结果：

> 爪子的**抓取点**和相机**刚性固定在一起**，所以抓取点在相机坐标系里的位置是
> **一个常数**，记作 `(tx, ty)`。

于是「爪子正下方对准物块」⟺「物块出现在画面里的 `(tx, ty)`」。
问题从"坐标换算"变成"**把观测量伺服到定值**"。

### 10.2 控制律

只有两个自由度参与平面运动：**底座旋转**与**径向伸缩**（高度只影响 `z`，不动 `x/y`）。
在线性化下走 `p = (底座脉冲, 伸缩脉冲)` 会让画面里的物块挪 `J·p`，其中

```
       底座每脉冲      伸缩每脉冲
J = [  base_dx       radial_dx  ]   ← 画面 x 位移（毫米/脉冲）
    [  base_dy       radial_dy  ]   ← 画面 y 位移
```

要让当前的画面误差 `e = (x, y) − (tx, ty)` 归零，就是 `e + J·p = 0`，即

```
p = −J⁻¹ · e
```

**`J` 是实测的**（探针，见 10.3），所以相机怎么装、歪多少度、朝哪个方向，全都不用假设。

### 10.3 标定（两步，都很快）

**目标读数 `(tx, ty)`**：把物块放到爪子附近，**用手**把爪子挪到"正好套住物块"的位置，
然后 `--set-target` 记录此刻的画面读数。它就是抓取点在相机系里的位置。

> 用手挪是安全的：本流程**不记绝对位置**，每次都重新看画面，手挪之后不会"以为"自己在别处。

**雅可比 `J`**：`--calibrate` 让程序每个轴走**两段同向**位移（第二段没有背隙损失，
斜率才是真的），量出画面挪了多少，然后退回原位。

### 10.4 为什么用脉冲驱动

用毫米就得先标 `mm_per_motor_rev`；用脉冲则**一个机器常数都不用**——只要知道
"每脉冲让画面挪多少毫米"。代价是精度受"一帧能分辨多少毫米"限制，且没有标定行程时
只能靠**脉冲预算**兜底（`max_total_pulses`）。

### 10.5 必须闭环，而且必须只看新帧

`J` 是线性化的，真实关系在大位移下会弯；背隙、丢步也让"发了 800 脉冲"不等于
"走了 800 脉冲的量"。所以每次都重新测量。

**"新帧"是硬要求**：动作前记一个时刻，动作后只接受晚于它的观测
（`CameraLink.frame(min_received_at=...)`）。用"多久算旧"挡不住"动作很快、旧帧也还新"
的情况——那时读到的是动作**之前**的坐标，闭环会以为没动过、再发一次，看起来像振荡。

### 10.6 失败路径

| 情况 | 表现 |
|---|---|
| 画面里没有物块 | 报错并列出实际收到了什么；一个动作帧都不发 |
| 画面里多个目标而没配判别条件 | 报错，**不猜**哪一个 |
| 雅可比奇异 | 报错。含义是"两个轴在画面里位移方向几乎重合"，凑不出任意方向 |
| 脉冲预算用完 | 报错。通常说明雅可比标反了或符号错了，先重标 |
| 迭代用尽 | 报出最后误差与总脉冲；先重标，再看是不是被线材挡住了 |

### 10.7 这套没做的事

- **不做回零**：位姿不靠回零建立，每次都是现测的，所以回零与否不影响这一步。
- **不动高度**：`z` 是第二步的事（下降到物块距镜头约 70 mm），用它自己的视觉伺服。
- **不碰 `mm_per_motor_rev` / `limits` / 平面标定**：那些是毫米驱动与固定相机才需要的。
