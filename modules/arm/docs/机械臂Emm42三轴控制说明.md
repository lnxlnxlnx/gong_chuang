# 机械臂 Emm42 三轴控制说明

> 适用对象：三台 ZDT Emm42 闭环步进电机组成的机械臂（地址 5 / 6 / 7）。
>
> 本文只写已确认的电机控制事实与操作边界。**机械臂现在只有"相对脉冲"和"按里程表的绝对脉冲目标"
> 两种用法**：毫米级绝对坐标（规划、位姿推算、回零建参考）已经退出，见第 8 节。
> 不得用机械硬限位试探行程。

## 1. 已确认的轴映射

| 轴 | 电机地址 | CW（`Direction.CW` / 字节 `00`） | CCW（字节 `01`） | 对外计量单位 |
|---|---:|---|---|---|
| 底座旋转 | 5 | 顺时针旋转 | 逆时针旋转 | 输出轴角度（°） |
| 上下 | 6 | 向上移动 | 向下移动 | 脉冲 / 电机角度 |
| 前后伸缩 | 7 | 向前移动 | 向后移动 | 脉冲 / 电机角度 |

上述地址和方向来自当前机械臂实物说明。三个地址必须与底盘的 1--4 地址保持唯一，才可挂在同一条
Emm42 总线上（`Robot.open` 会在开串口之前核对）。

## 2. 驱动器的已证实参数

来源：`modules/motor/docs/Emm_V5.0步进闭环驱动说明书Rev1.3.pdf`，印刷页 36--37（PDF 页 37--38）。

| 项目 | 值 | 使用要求 |
|---|---|---|
| 通讯接口 | UART，115200 bps、8N1 | 必须与 USB-TTL 和驱动器菜单一致 |
| 方向编码 | `00` = CW；`01` = CCW | 本机械臂各轴的物理含义见上表 |
| 速度范围 | `0..3000 RPM` | 为避免撞击，机械臂用小转速；具体值见 `modules/arm/config.json` 的 `motion.rpm`（当前 `80 RPM`） |
| 加速度档位 | `0..255` | `0` 为无曲线加减速；当前配置 `motion.acceleration` = `200` |
| 支持细分 | `1..256`，菜单默认 16 | 软件不能假定为 16；先读取或人工确认每台的 `MStep` |
| 16 细分的脉冲数 | 3200 脉冲/电机圈 | 仅在 1.8° 电机且 `MStep=16` 时成立 |
| 位置模式 | 相对或绝对 | `RobotArm` **只发相对帧**（绝对脉冲目标也是按里程表算成增量再发相对帧）；驱动器自己的绝对模式留给 `Emm42Driver.move_absolute*` 直接调用 |
| 停止 | `FE 98` | 速度和位置模式均可立即刹车 |

当前 `modules.motor.drive.emm42.Emm42Driver` 默认按 `pulses_per_revolution=3200` 工作。若实际细分不是 16，
必须在构造驱动器时传入正确值；否则所有角度、脉冲上限都会错。

## 3. 可复用的 Emm42 命令

| 目的 | 命令格式 | 当前 Python API | 备注 |
|---|---|---|---|
| 使能扭矩 | `ID F3 AB 01 00 6B` | `enable(True)` / `RobotArm.enable_all()` | 每次位置移动前需要使能；`RobotArm.open` 已做过 |
| 失能松轴 | `ID F3 AB 00 00 6B` | `enable(False)` / `RobotArm.disable_all()` | 测试结束和异常清理时执行 |
| 相对位置移动 | `ID FD dir rpm(2B) acc pulses(4B) 00 00 6B` | `move_relative(...)` / `move_relative_pulses(...)`；`RobotArm.rotate_cw` 等 | 机械臂唯一允许的运动帧格式 |
| 绝对位置移动 | `ID FD dir rpm(2B) acc pulses(4B) 01 00 6B` | `Emm42Driver.move_absolute*`（`RobotArm` 不用） | 前提是驱动器内部计数器有效；**脉冲数 0 是合法的**，那正是"回原点" |
| 立即停止 | `ID FE 98 00 6B` | `stop()` | 紧急停止；之后仍应失能并关闭串口 |
| 总线同步启动 | `00 FF 66 6B` | `trigger_sync_motion()` | `RobotArm.move_axes` 用它让多轴同时起步 |
| **触发回零** | `ID 9A mode sync 6B` | `home(mode)` | mode：`00` 单圈就近、`01` 单圈方向、`02` 多圈碰撞、`03` 多圈限位开关。**前提：已使能扭矩、未触发堵转保护、单圈零点值有效**。`RobotArm` 不再封装回零（见第 8 节） |
| **设单圈零点** | `ID 93 88 01 6B` | 未封装（用驱动器菜单 `O_Set → Set O` 即可） | 把**当前**姿态设成单圈回零零点，写进驱动器；任意姿态都能设 |
| 清当前位置计数 | `ID 0A 6D 6B` | 未封装 | 只清当前位置/误差/脉冲数，**掉电即失效**；与 `0x93` 不是一回事 |
| 读实时位置 | `ID 36 6B` | `read_position()` | 返回 `符号 + 4 字节`；单位为 **65536 = 一圈** |
| 读单圈编码器 | `ID 31 6B` | `read_encoder()` | 一圈 0–65535，**分不清圈数** |
| 读电机状态 | `ID 3A 6B` | `read_status()` | 使能 / 到位 / 堵转 / 堵转保护四位 |
| 读回零状态 | `ID 3B 6B` | `read_homing_status()` | 编码器就绪 / 校准表就绪 / 正在回零 / 回零失败 |
| 读实时转速 | `ID 35 6B` | 未封装 | 返回 `符号 + 转速` |
| 读位置误差 | `ID 37 6B` | 未封装 | 返回 `符号 + 误差值` |
| 读回零参数 | `ID 22 6B` | 未封装 | 返回模式/方向/转速/超时/碰撞阈值/是否上电自动回零 |

位置帧的 `pulses` 是 4 字节无符号数，协议上限为 `0xFFFFFFFF`。机械臂封装不能把这个协议上限当作
实际允许范围，它用的是 `modules/arm/config.json` 的 `motion.max_pulses`。

### 3.1 回包怎么认（`Response` 菜单 + 共用总线）

说明书默认 `Response=Receive`，这时控制命令会立即回 `ID FF 02 6B`。本机械臂读到的配置是
**5 号回包、6/7 号不回**，所以 `modules/arm/hardware.json` 逐轴声明 `expect_ack`；
底盘四轮是 `true`。

总线是 arm 与 chassis 共用的，所以"回包"里混着别人的帧、驱动器异步发的到位包（
`Response=Reached/Both` 时的 `ID FD 9F 6B`）和被打坏的半帧。`Emm42Driver._read_reply_for`
的规矩因此是：

- **地址 + 功能码都对得上**才算自己的回包（广播帧没有地址，只认功能码）；
- `FD 9F` 到位包**永远**不是命令 ACK，一律丢掉继续等；
- 尾字节不是 `0x6B` 的整帧只有地址对得上时，只丢一个字节重新对齐。

"驱动器回过话（`02`/`E2`/`00 EE`）"和"什么都没等到"要分开处理：前者是真结论，立刻报错；
后者可能只是回包被打坏了，幂等命令会重发（相对位置帧**永不重发**——重发就是让轴多走一段）。

### 3.2 两个"圈"的单位不要混

位置**命令**（`0xFD`）用**脉冲**：手册写明「1.8° 步进电机、16 细分，发送 3200 个脉冲转一圈」，
所以 `pulses_per_revolution = 3200`。

位置**读回**（`0x36`/`0x31` 等）用**编码器单位**：手册注「经过线性化校准后，内部对编码器值
进行了 4 倍频，一圈的数值是 0-65535」，所以 **65536 = 一圈**。两者相差 **20.48 倍**，
换算时极易搞错。

另外 `0x36` 的读数只有**一圈**的量程。手册的例子把 `0x00010000` 算成 `-360.0°`（不取模），
所以它到底是不是多圈计数，手册没有说死——真机验证：断电后手动把轴转过一圈再上电，
读 `0x36` 看值是否体现多圈。**这直接决定单圈回零能不能当可靠的绝对参考。**

## 4. 运动量换算（读数用，不是运动 API）

### 4.1 基础量

令：

- `PPR`：每电机圈脉冲数；16 细分时为 `3200`。
- `g`：电机转数 / 输出轴转数。减速器的常规"6:1 减速"对应 `g = 6`，即电机转 6 圈、输出轴转 1 圈。
- `L`：直线机构的每输出圈位移（mm/圈）。丝杠为导程；同步带为主动轮有效周长；齿轮齿条为小齿轮节圆周长。

### 4.2 5 号底座轴

`modules/arm/hardware.json` 当前取 `g = 5`（`axes.base.reduction_ratio`）。装配图上通常记为
"1:6" 之类，含义必须在铭牌上确认；**所有输出轴角度注释都依赖它**，差 20% 在 `r = 150 mm` 处
就是 30 mm 以上的定位偏差，所以先用实验 A0（见 `modules/grasp/docs/抓取坐标链路.md`）实测一次：
命令底座累计走 16000 脉冲，回到原位即 `g = 5`。

```text
输出轴角度(°) = 脉冲数 * 360 / (PPR * g)
脉冲数 = round(|输出轴角度| * PPR * g / 360)
```

在 `PPR=3200` 且 `g=5` 时：

- 输出轴一圈 = `16000` 脉冲；
- 1000 脉冲 = `22.5°` 输出轴转角；
- 1 脉冲 = `0.0225°` 输出轴转角。

（早期文档按 `g=6` 给出的 `19200` 脉冲与 `18.75°` 已作废。）

### 4.3 6、7 号直线轴

```text
位移(mm) = 脉冲数 * L / (PPR * g)
脉冲数 = round(|位移(mm)| * PPR * g / L)
```

6 轴与 7 轴必须分别记录自己的 `mm_per_motor_rev = L / g`。公式里永远只出现这个商，所以
**不必拆机分别量 `L` 和 `g`**：直接测「电机转一圈走多少毫米」即可（实验 B/C）。
当前两者都是 `61.0 mm/电机圈`。

> **代码现在不读这两个值**：抓取走的是脉冲闭环（每像素多少脉冲），不需要毫米换算。
> `mm_per_motor_rev` 作为测量记录保留在 `hardware.json` 里，供换算与人工核算。

## 5. 机械臂保守测试边界

测试参数集中在 `modules/arm/config.json`。入口和控制器都会读取同一份配置，并在打开串口前拒绝超出范围的输入：

| 参数 | 允许值 | 原因 |
|---|---|---|
| 运动模式 | 只发相对位置帧 | `RobotArm` 不碰驱动器的绝对模式 |
| 速度 | `motion.rpm`，当前 `80 RPM` | 每个动作可用 `rpm=` 单次覆盖 |
| 加速度 | `motion.acceleration`，当前 `200` | 每个动作可用 `acceleration=` 单次覆盖 |
| 单次脉冲数 | `1..motion.max_pulses`，当前 `1..11000` | 超出时**在发帧之前**抛 `ValueError` |
| 单次方向 | 只允许该轴表中定义的 CW/CCW | 物理方向不可由调用方自由猜测 |
| 多轴同步 | 允许，但底座与伸缩并行受 `DEFAULT_PARALLEL_ROTATION_LIMIT_PULSES`（600 脉冲）限制 | 伸出状态下横扫会把整条臂扫过工作区 |
| 绝对行程 | 不再检查 | 绝对坐标那套已退出；见下面的提醒 |

> **`max_pulses` 必须小于等于该轴的真实行程。** 现在只剩这一个上限，而它当前是 `11000`：
> 底座一圈 = `16000` 脉冲（`g=5`），升降/伸缩一圈 = `3200` 脉冲，按 `limits` 折算升降 ≈ `9102`、
> 伸缩 ≈ `9395` 脉冲。也就是说 `11000` 比两根直线轴的整段行程还大——一条满上限的命令会直接顶到
> 止挡上，而 5/6/7 号驱动器撞停也不会报错。要把这个上限调到 `9000` 以下再跑满行程的动作。

每次真机测试的固定生命周期：使能目标轴 → 发送一条相对位置帧 → 等它走完 → 停止 → 失能 → 关闭串口。
发生异常或 `Ctrl+C` 时也必须执行停止、失能、关闭。

## 6. 实施前必须确认的机械参数

| 轴 | 必填数据 | 用途 |
|---|---|---|
| 5 | 减速器铭牌/装配图中"输入转数 : 输出转数"的明确定义；安全转角范围；零位基准与限位方式 | 固化角度换算、拒绝越界旋转 |
| 6 | 丝杠导程或等效 `L`；是否另有减速器；最低/最高机械位置；零位与限位方式 | `mm <-> 脉冲` 换算和上/下行程 |
| 7 | 丝杠导程或等效 `L`；是否另有减速器；最短/最长伸出量；零位与限位方式 | `mm <-> 脉冲` 换算和前/后行程 |
| 全部 | 每台 `MStep` 细分值、串口端口、供电和急停措施 | 保证脉冲换算和真机通信正确 |

不能用堵转保护或机械碰撞来确定零位、导程、方向或行程。若没有限位开关，首次参数标定必须在
远离两端机械止挡的位置开始，并由操作者持续观察。

## 7. 封装的验收标准

- 轴 5/6/7 的对象地址分别固定为 5/6/7，CW 物理方向与第 1 节一致。
- 任意测试调用若脉冲不在 `1..motion.max_pulses`，必须在发送串口帧前抛出 `ValueError`；
  速度和加速度必须使用配置中的值（或被显式覆盖）。
- 在 `MStep=16`、5 轴 `g=5` 的前提下，1000 脉冲必须换算为 `22.5°` 输出轴角度。
- 离线测试必须验证帧地址、方向字节、速度、加速度、脉冲上限、换算公式和异常清理路径，
  且不得打开真实串口。

## 8. 当前实现

实现文件：`modules/arm/runtime.py`（`RobotArm`）。它从 `modules/arm/config.json` 读运动参数、
从 `modules/arm/hardware.json` 读三轴地址与传动常数，并共享一条步进总线（`Robot.open` 打开、
arm 与 chassis 借用）。没有速度模式。

| 物理动作 | API | 返回值 |
|---|---|---|
| 底座顺/逆时针 | `rotate_cw(pulses, *, rpm=None, acceleration=None, wait=True)` / `rotate_ccw(...)` | `MotionReport`（或 `wait=False` 时 `MotionTicket`） |
| 向上/下 | `move_up(pulses, ...)` / `move_down(pulses, ...)` | 同上 |
| 向前/后 | `move_forward(pulses, ...)` / `move_backward(pulses, ...)` | 同上 |
| **按里程表走绝对脉冲位置** | `move_axis_to_motor_pulses(axis_name, pulses, ...)` / `move_axis_to_motor_degrees(axis_name, degrees, ...)` | `MotionReport`；已经在目标上就一帧都不发（幂等） |
| **多轴同时起步** | `move_axes({轴名: 脉冲}, *, mode="same_start" \| "serial", wait=True)` | 报告元组 / 票据 |
| 全轴清理 | `stop()`、`disable_all()`、`close()` | 无 |

**按里程表走绝对位置**用的是"相对**原点**累计了多少脉冲"（`turns_state`），不是驱动器的绝对模式：
目标是读数而不是增量，所以同一条命令可以反复发。**不取模**——行程都超过一个电机圈
（底座 1800°、升降 1024°、伸缩 1057°），`1048°` 与 `328°` 是两个不同的位置。启动时读数从哪起算
由 `modules/arm/hardware.json` 的 `initial_motor_degrees` 决定，见第 9 节。单帧装不下的增量会
自动拆段（拆段要求 `wait=True`）。

**`move_axes`** 默认走多机同步三步法：逐轴发 `0xFD`（同步标志 = 01）缓存 → 帧间留
`DEFAULT_INTER_FRAME_SECONDS`（30 ms，CH340 上背靠背两条位置帧会双双失效）→ 广播
`00 FF 66 6B` 让它们一起起步。`mode="serial"` 改按 抬升 → 伸缩 → 底座 → 下降 的安全顺序逐轴走完。

**已经退出的部分**：`motion_plan`（绝对 XYZ/圆柱规划）、位姿推算与 `ArmPose`、
`home_axis`/`home_all`、`move_axis_to_zero`/`move_all_to_zero`、`move_cylindrical_by`/`move_by`、
`move_base_degrees`/`move_lift_mm`/`move_radial_mm`。生产路径（`main.py`、`app/gripper.py`、
`modules/grasp`）用的是**方向原语 + `move_axis_to_motor_degrees` + `move_axes`**，
一次毫米级绝对定位都没用过，所以整条链连同它的测试一起删掉了。回零请用驱动器面板
（`O_Set`）或直接 `Emm42Driver.home(mode)`。

`wait=True` 的实现是按说明书公式估算耗时：

```
总耗时 ≈ rpm * (256 - acceleration) * 50µs + 脉冲数 / (rpm * 脉冲每圈 / 60) + 到位余量(0.15s)
```

返回值 `MotionReport` 里的 `estimated_seconds` 就是这个估算值；`wait=False` 时调用方自己拿它去等
（或者交给 `robot.motion.begin()` 的动作组一起等）。需要毫秒级精确时可以切到轮询模式
（`RobotArm.open(wait_mode=WAIT_IN_POSITION)`，`0x3A` 的 `&0x02` 到位位），默认仍走估算。

参数约定与底盘轮子完全一致（见 `modules/motor/drive/motion.py`）：`pulses` 必填、`rpm` / `acceleration` 可选、
`wait=True`（默认）等到动作走完再返回。**这一条很重要**：不等待就会在下一条位置帧发出时覆盖上一条的目标，
现象是"上一个动作没执行完"。

在项目根目录运行统一测试菜单并选择机械臂（菜单 2）；串口从 `modules/motor/hardware.json`
（步进总线唯一来源）读取。每个动作走 `motion.default_pulses`，每步都需要操作员回车确认，
输入 `q` 停止后续动作。正常结束、异常和 `Ctrl+C` 都会停止三轴、失能并关闭串口。

```powershell
python test.py
```

## 9. 里程表的启程读数（`initial_motor_degrees`）

机械臂只发相对帧，所以"程序启动那一刻轴在哪"必须由外部给出。现在只有一条路：**在配置里声明启程读数**。

```json
"initial_motor_degrees": { "base": 0.0, "lift": 0.0, "extension": 270.0 }
```

- 单位是**电机角度**（`3200 脉冲 = 360°`），带符号、**不取模**。它给的是 `RobotArm.turns_state`
  （命令脉冲里程表）的**起点**：上面这份配置下启动读数是 `extension: +2400 脉冲 (+270.00°)`。
  于是 `move_axis_to_motor_degrees("extension", 0)` 会真的把那 2400 脉冲收回去，而不是因为
  "读数已经是 0"一帧都不发。
- 它是**声明，不是动作**：不发电、不动轴。声明错了，`move_axis_to_motor_pulses` /
  `move_axis_to_motor_degrees` 这类"按里程表走绝对位置"的动作就会整体偏一个常数——
  伸缩上 2400 脉冲 = 45.75 mm（61 mm/电机圈），接近总行程 179.1 mm 的四分之一。
- **回零之后要自己清零**：`RobotArm` 不再封装回零，所以没有代码路径会自动 `mark_origin`。
  用面板回零（或 `Emm42Driver.home()`）之后，要么把 `initial_motor_degrees` 改成 `0.0`，
  要么调一次 `arm.turns_state.mark_origin()`，否则按里程表的绝对目标会整体偏一个常数。
- 载入时就拒绝超过该轴总行程的声明（伸缩 1057°、升降 1024°、底座 1800°，由 `limits` 折算）；
  缺行程标定的轴跳过这项检查。

> **符号与方向必须现场核一次。** 单圈编码器读数（`0x31`，一圈 0–65535）报的 270° 既可能是
> `+2400` 脉冲，也可能是 `-800` 脉冲（−90°）：两者**相差整整一圈 = 61 mm**，不是同一个点。
> 用 `0x36`（带圈数的位置）或者直接量机械位移确认，别拿单圈读数猜。声明反了的后果不是报错，
> 而是之后每次按里程表的绝对定位都偏**整整一圈**（3200 脉冲 = 61 mm）：目标要么够不到、要么
> 正好顶在止挡上——而 5/6/7 号驱动器撞上止挡也不会回任何包。
