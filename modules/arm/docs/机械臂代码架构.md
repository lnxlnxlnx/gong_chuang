# 机械臂代码架构

机械臂控制分三层，依赖方向只能从上到下：

```text
modules/arm/test/manual/arm.py               交互式真机测试
                 |
                 +--> runtime.py（RobotArm）   三轴动作：方向原语 + 按里程表的绝对脉冲目标 + move_axes
                 |          |
                 |          +--> drive/kinematics.py              电机角度 ↔ 脉冲（纯换算）
                 |          |
                 |          +--> modules/motor/drive/motion.py     位置模式耗时估算（与底盘轮子共用）
                 |          |
                 |          +--> modules/motor/drive/emm42.py  Emm42 串口协议帧
                 |
                 +--> config.py                JSON 读取、类型和范围校验
                            |
                            +--> config.json   运动调参（rpm / acceleration / 脉冲上限）
                            +--> hardware.json 硬件事实（地址、减速比、导程、启程读数）
```

## 改参数

日常调参改 `modules/arm/config.json`，换机器/换接线改 `modules/arm/hardware.json`，都不改 Python：

**`config.json`**（运动调参）

- `motion.default_pulses`：命令行未传 `--pulses` 时使用的脉冲数。
- `motion.max_pulses`：CLI 和 `RobotArm` 都会拒绝超过该值的脉冲数（**必须 ≤ 该轴真实行程**，
  见 `机械臂Emm42三轴控制说明.md` 第 5 节的提醒）。
- `motion.rpm`、`motion.acceleration`：所有位置模式帧共同使用的速度和加速度。

**`hardware.json`**（硬件事实）

- `axes.*.motor_id`：三台驱动器地址；必须唯一，且不能和底盘四轮冲突。
- `axes.*.expect_ack`：这台驱动器的 `Response` 菜单会不会回 4 字节 ACK（当前 5 号 `true`，
  6/7 号 `false`）。
- `axes.base.reduction_ratio`：5 号底座的减速比（当前 5），用于输出轴角度换算。
- `axes.{lift,extension}.mm_per_motor_rev`：直线轴电机一圈走多少毫米，即 `L / g`
  （实验 B/C 标定，见 `modules/grasp/docs/抓取坐标链路.md`）。**代码现在不读它**，
  留作测量记录。
- `initial_motor_degrees`：**程序启动那一刻**每根轴相对原点的电机角度（`3200 脉冲 = 360°`），
  没写的轴按 0。它描述的是**状态**，不是传动常数：换爪子、重新对齿或重装电机之后，某根轴的
  机械初始位可能不在原点上（当前 7 号伸缩是 `270.0` = 2400 脉冲 = 45.75 mm），就在这一项里
  如实声明。**回零之后要自己把它改成 0（或调 `turns_state.mark_origin()`）**——`RobotArm`
  不再封装回零，没有代码路径会自动清零里程表。完整语义与符号陷阱见
  `modules/arm/docs/机械臂Emm42三轴控制说明.md` 第 9 节。
- `limits` / `safe_pose` / `homing`：绝对坐标那套已退出，这三项只做加载时校验
  （`limits` 还用于检查 `initial_motor_degrees` 有没有超出行程），不再参与任何运动决策。

`kinematics.py` 是**纯计算**：不打开串口、不读配置文件，所以能完全离线测试。

配置载入时会拒绝缺失轴、重复地址、超出驱动器范围的速度或加速度、默认脉冲大于最大脉冲、
初始电机角超过该轴总行程，以及把 `reduction_ratio` / `mm_per_motor_rev` 填到错误的轴上。
配置无效时，程序会在打开串口和发送运动帧之前退出。

## 模块职责

- `modules.motor.drive.emm42.Emm42Driver`：只组装、发送和校验 Emm42 指令帧；不知道机械臂轴名称
  或行程。位置模式既接受角度（`move_relative`）也接受脉冲数（`move_relative_pulses`）。
- `modules/motor/drive/motion.py`：机械臂和底盘共用的运动参数约定与耗时估算
  （`estimate_move_seconds`）。`wait=True` 用说明书的曲线加减速公式估算耗时；要实测就切
  `WAIT_IN_POSITION` 轮询 `0x3A` 的到位位。
- `runtime.RobotArm`：把"向上""后缩"等机械语义映射为配置中的电机地址和 CW/CCW，统一执行
  相对位置模式、脉冲校验、里程表记账与报告；`pulses` 必填，`rpm` / `acceleration` / `wait` 可选。
  按里程表的绝对目标（`move_axis_to_motor_degrees` / `move_axis_to_motor_pulses`）和多轴
  同时起步（`move_axes`）也在这里。
- `config.load_arm_config()`：把两份 JSON 转成已校验的 `ArmConfig`，是配置文件和 Python 代码
  之间唯一的适配点。
- `modules.arm.test.manual.arm`：仅控制人工确认、执行顺序和清理；不保存运动参数。

离线测试通过注入 `ArmConfig` 和内存串口验证配置到帧字段的完整链路，不会打开真实串口。
