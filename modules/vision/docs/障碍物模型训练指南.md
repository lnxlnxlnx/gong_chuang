# 障碍物模型训练指南

本文对应 `models/data` 里那批「障碍物」图片，讲清楚从数据到模型上车的完整流程。
训练脚本已经放在 `training/` 下，两条命令就能跑通。

- `modules/vision/training/prepare_dataset.py`：把扁平的数据集切分成 ultralytics 需要的 `images/labels` + `train/val` 结构，并生成 `data.yaml`；顺便校验标注格式。
- `modules/vision/training/train.py`：调用 ultralytics 训练，可选导出 ONNX。

## 1. 数据现状（已核对）

| 项目 | 实际情况 |
| --- | --- |
| 图片 | `models/data/image/`，303 张，1280×720 JPG，文件名形如 `black (1).jpg` |
| 标注 | `models/data/labels/`，303 个同名 `.txt`，**图片与标注一一对应，无缺漏** |
| 标注格式 | YOLO 检测格式：`类别 cx cy w h`，全部归一化到 0~1 |
| 类别 | `classes.txt` 只有一行 `obstacle`，即**单类别** |
| 框数量 | 每张图恰好 1 个框，共 303 个框，坐标全部合法 |

因为只有一个类别，训练出来的模型只会输出「obstacle」这一类，这点在替换机器人上现有模型时要注意（见第 6 节）。

## 2. 训练环境（已实测可用）

训练用的不是系统 Python，而是 conda 的 `torch` 环境：

```
conda activate torch
```

里面已装好：Python 3.9.23、`ultralytics 8.3.233`、`torch 2.8.0+cu126`、`torchvision 0.23.0+cu126`。
GPU 是 RTX 4060 Laptop（8 GB 显存），`torch.cuda.is_available()` 为 `True`。

> 系统 Python 3.12.4 里没有 torch/ultralytics，直接用它跑训练会失败。

会额外把 `best.pt` 导出成 `models/best_obstacle.onnx`（固定 640×640 输入，`modules.vision.YOLOv8ONNXDetector` 要求固定输入，所以脚本里 `dynamic=False`）。
导出后怎么测、怎么接摄像头，见第 4 节。

## 4. 训练完怎么测

分三层：先用 ultralytics 看指标和预测图，再用项目自己的 ONNX 推理链路在图片上验收，最后接摄像头。

### 4.1 看指标（ultralytics 自带命令）

```powershell
# 在验证集上算 mAP，曲线和混淆矩阵存到 models\runs\val_check
yolo detect val model=models\runs\obstacle\weights\best.pt data=models\dataset\data.yaml project=models\runs name=val_check

# 在图片 / 文件夹 / 视频上画框，结果存到 models\runs\predict
yolo detect predict model=models\runs\obstacle\weights\best.pt source=models\dataset\images\val project=models\runs name=predict
```

`yolo` 命令随 ultralytics 装在 `torch` 环境里（已确认可用，版本 8.3.233）。把 `source` 换成你自己的图片路径
就能测训练集之外的图。

### 4.2 用终端菜单测（推荐，不用记参数）

先导出 ONNX：

```powershell
python training\train.py --model yolo11n.pt --export-onnx     # 产出 models\best_obstacle.onnx
```

然后在项目根目录打开测试菜单，选 `15`：

```powershell
python test.py
```

接下来只回答几个问题（第一步先问「怎么测」，只有需要模型的模式才会再问模型）：

```
请选择测试方式：
  1. 摄像头实时预览
  2. 验证集图片批量测试  models\dataset\images\val  （61 张）
  3. 指定图片文件夹
  4. 单个图片或视频文件
  5. 摄像头自检（0–3 号挨个试，看哪个能出画面；不需要模型）
```

- 选 **1**：打开摄像头实时预览，画面上的框和类名就是检测结果，按 `q` 退出；
- 选 **2**：跑验证集那 61 张图，**不需要摄像头、不需要真机**；

- 选 **5**：摄像头自检，逐个试 0–3 号并报告分辨率、平均亮度，用来确认该填哪个 `camera_id`；
- 类别表由模型那一问自动决定：选 1 就是单类 `obstacle`，选 2 用配置里的四类，
  **不会出现菜单 9 那种类名错位**；
- 终端逐张打印检出结果，带框图片写到 `output\vision_predict`，直接打开看即可。

> 预览窗口的标题固定是英文 `obstacle model test`。OpenCV 在 Windows 下用 ANSI 接口建窗口，
> 中文标题会显示成 `????`，所以标题保持英文，所有中文提示都打在终端里。

### 4.3 菜单 9 与原有视觉演示

`python test.py` 选 9 是原有的视觉演示，加载哪个模型、有哪些类别、输入多大，全部读
`modules/vision/config.json` 的 `model` 块（见 README「模型」一节）。**不在这份配置里的类别名，
一律按错位处理**：框的坐标由模型给出，类名是按索引查表得到的，表错了框还是准的、名字会整体错位。

所以把训练好的模型换上去时要改的是配置，不是代码：

```json
"model": { "class_names": ["obstacle"], "input_size": 640, "materials": null }
```

`modules/vision/drive/yolov8.py::DEFAULT_CLASS_NAMES` 只是**没有配置时**的兜底表，
正常情况下不需要动它。`modules/vision/training/train.py` 在类别数与当前配置不一致时会打印提醒。

要在代码里画测距读数，用 `modules.vision.DistanceEstimator`，它按「类名 → 实测宽度(mm)」查表，
例如 `{"obstacle": 60}`。

### 4.4 怎样算训好了

- `mAP50` 单类、场景固定的数据通常能到 0.95 以上（看 `yolo detect val` 的输出或 `results.png`）；
- 更要看带框的预测图：框贴不贴、有没有漏检误检；
- 一定要拿**没参与训练的新图**（换背景、换距离、换光照）再测一遍，这才是真实泛化能力。

## 5. 参数怎么选

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--model` | `yolov8n.pt` | 数据量小，n 最快最省显存；想提精度用 `yolov8s.pt`，显存不够就降 `--batch`。本地已有 `yolo11n.pt`（见第 8 节），可直接 `--model yolo11n.pt` |
| `--epochs` | 100 | 300 张单类数据 100~300 轮都合理，靠 `--patience` 早停 |
| `--imgsz` | 640 | 必须是 32 的倍数。原图 1280×720，障碍物框约 216×403 像素，640 足够；小目标多时可试 960 |
| `--batch` | -1 | 自动适配显存；8 GB 显存跑 yolov8n@640 一般是 16 左右。显存不足就写 `--batch 8` |
| `--device` | `0` | 第一块 GPU；`cpu` 强制用 CPU（很慢，仅排错用） |
| `--workers` | 8 | Windows 上若卡在启动阶段，改 `--workers 0` |
| `--fraction` | 1.0 | 只用一部分训练集，冒烟测试用 |

`--resume` 可以从 `models/runs/obstacle` 里的中断点继续。

> 结果怎么看：先看 `results.png` 里 `mAP50-95` 和 loss 曲线是否收敛，
> 再看 `val_batch*_pred.jpg` 的框贴不贴。验证集只有 61 张，指标波动会比较大，
> 别把单个百分点的差异当回事，以实际摄像头前的效果为准。

## 6. 换成机器人上跑

### Windows（开发机，ONNX）

`modules.vision.default_model_path()` 读 `modules/vision/config.json` 的 `model` 块；Windows 下默认取 `models/best.onnx`。两种用法：

```python
from vision import create_detector

# 方式一：直接用新模型，并声明单类别表
detector = create_detector("models/best_obstacle.onnx", class_names=["obstacle"])
```

或者把新模型改名成 `models/best.onnx`，再把 `model.class_names` 改成 `["obstacle"]`
（`model.input_size` 也要跟着改成导出时的 `--imgsz`）。

⚠️ **关键点：类别表必须和模型对上。** 类名是按索引查 `model.class_names`（没配置时是
`yolov8.py::DEFAULT_CLASS_NAMES`，当前是四类 `red`/`yellow`/`blue`/`green`）得到的，而你这份数据只有 1 类。
模型输出的框坐标是对的，但如果不同步类别表，画面上打印的类名会全部错位。改 `model.class_names`，
或者像上面那样给 `create_detector()` 传 `class_names=["obstacle"]`。
`modules/vision/training/train.py` 在类别数不一致时会主动打印这段提醒。

### Jetson（板子，TensorRT）

ONNX 不能直接给 `YOLOv8Detector` 用，TensorRT engine 必须**在目标板子上导出**（TensorRT 版本和 GPU 架构必须一致），
所以把导出的 ONNX 拷到 Jetson 后在板子上构建：

```bash
cd ~/gong_chuang
/home/pi/miniforge3/envs/tensorrt/bin/python -m modules.vision.training.build_engine --force
```

它会读 `model` 块确定的 ONNX/engine 路径、用 `trtexec` 转换，并接着跑一次验收。
完整说明（前置环境、实测耗时、常见故障）见 [Jetson模型部署.md](Jetson模型部署.md)。

### 单目测距

`modules.vision.DistanceEstimator` 是按「类名 → 真实宽度(mm)」查表算距离的，新增类别要在 `real_widths` 里补上
`"obstacle"` 的实测宽度，否则该类会返回 `None`（不估距）。

## 7. 300 张够不够

单类、每张 1 个框、场景单一（文件名都是 `black`，大概率是同一背景同一光照），
训一个「能认出这个障碍物」的模型足够了；但泛化到别的背景、别的光照就要补数据。建议：

- 多拍不同背景、不同光照、不同距离和角度，目标大小跨度拉大；
- 加一些**不含障碍物的背景图**并给空标注文件（ultralytics 允许空 `.txt`），能显著压误检；
- 一张图里放多个障碍物，让模型学会多目标（现在每张只有 1 个框）；
- 训练时的在线增强（马赛克、翻转、HSV）ultralytics 默认已开，不用自己写。

## 8. 预训练权重下载不下来怎么办

首次训练时 ultralytics 要去 GitHub 下载 `yolov8n.pt`（约 6 MB）。实测这台机器访问 github.com
**时通时断**（大量连接超时、连接被重置），ultralytics 内部会自动重试 3 次，仍可能失败并报
`ConnectionError: Download failure for https://github.com/ultralytics/assets/... Retry limit reached.`。

按省事程度，有四种办法：

**办法一：直接用已经下好的 YOLO11n 权重（推荐）**

验证训练流程时 `yolo11n.pt` 已经成功下载到项目根目录（它是 AMP 检查时下载的，已验证能正常加载，
是 80 类 COCO 预训练权重）。直接用：

```powershell
python training\train.py --model yolo11n.pt
```

YOLO11n 比 YOLOv8n 更新、精度更高，导出的 ONNX 结构与 `modules/vision/drive/yolov8.py` 的解码逻辑完全兼容。
建议把它挪进 `models\` 一起保存：

```powershell
Move-Item yolo11n.pt models\
python training\train.py --model models\yolo11n.pt
```

**办法二：从 HuggingFace 国内镜像手动下载**

```powershell
curl.exe -L -o yolov8n.pt https://hf-mirror.com/Ultralytics/YOLOv8/resolve/main/yolov8n.pt
```

权重放在项目根目录即可，ultralytics 会优先用本地文件，不再联网。想要更大的模型就把文件名换成
`yolov8s.pt` / `yolov8m.pt`（同一镜像仓库里都有）。

**办法三：换网络或挂代理再跑一次**

github 只是不稳定，重跑往往就成功了。

**办法四：完全离线，从零训练**

```powershell
python training\train.py --model yolov8n.yaml --epochs 300
```

`yolov8n.yaml` 只是网络结构定义，随 ultralytics 一起装在本地，不需要任何下载。代价是没有预训练权重、
收敛慢很多，300 张单类数据建议把轮次加到 300 以上。注意：从零训练跑 3 轮的 mAP 几乎为 0 是正常现象，
不能拿短轮次结果下结论。

## 9. 常见问题

- **图片名带空格和括号**（`black (1).jpg`）：没问题，ultralytics 从磁盘列表读，不经过 shell。
- **路径含中文**：本项目路径没有中文；如果换到含中文的目录，注意用 UTF-8 终端。
- **Windows 上训练卡住不动**：`--workers 0`。
- **显存不足（CUDA out of memory）**：降 `--batch`（如 8）、降 `--imgsz`（如 512），或换更小模型。
- **首次训练会联网下载** `yolov8n.pt`（约 6 MB）：下载不下来时见第 8 节。
- **ultralytics 设置文件**：默认在 `%APPDATA%\Ultralytics\settings.json`，属正常行为，可以不管。
- **预览窗口标题显示成 `????`**：OpenCV 在 Windows 下画不出中文窗口标题，菜单 15 的标题固定用英文
  `obstacle model test`，中文提示都在终端里。
- **摄像头打开了但没有画面**：先在菜单 15 选 `5` 做摄像头自检，它会逐个试 0–3 号并打印分辨率和平均亮度。
  实测这台机器是 0、1 号可用（`640x480`，平均亮度 127 / 160），2、3 号不存在。
  自检显示「能打开但取不到画面」或「全黑」时，依次检查：是不是别的程序占了摄像头（相机、钉钉/腾讯会议、
  浏览器网页）、Windows 隐私设置里有没有允许桌面应用访问摄像头、以及 `modules/vision/config.json` 里的 `camera_id`
  是否对上。预览时终端每 30 帧打印一次 FPS 和检出数量，看不到这行说明卡在取帧或推理上。
