# 工位识别：三圆环、叠放位、两点测量与停稳门控

这一份文档讲**物料定位之外**的那几件事：工位摆正了没有（三圆环 / 叠放位）、
画面上的两点距离、以及"转盘到底转过没有"。

它们和物料定位共用同一个 ``Vision`` 会话与同一份 ``config.json``，但**判据没有一处共用**：
物料定位认颜色与顶面，工位识别认几何（圆环的共线性、基准线的倾角）。
所以它们是独立的检测器，不是物料定位的一个开关。

| 能力 | 模块 | 会话入口 | 真机菜单 |
|---|---|---|---|
| 三圆环工位识别 | ``modules.vision.drive.ring_station`` | ``Vision.detect_ring_station()`` | 22 |
| 叠放位识别 | ``modules.vision.drive.stacked_ring`` | ``Vision.detect_stacked_ring()`` | 23 |
| 两点像素测量 | ``modules.vision.drive.pixel_measure`` | ``Vision.pixel_distance()`` | 24 |
| 环心（单环 / 三环，机械臂对准用） | ``modules.vision.drive.numbered_ring`` | ``Vision.locate_ring()`` / ``detect_numbered_rings()`` | 26 |
| 停稳门控 | ``modules.vision.drive.motion_gate`` | ``Vision.measure_settled(require_motion=True)`` | — |
| 焦距 / 台面深度标定 | — | — | 25 |

## 一、三圆环工位识别

### 为什么不直接取"最大的三个圆"

画面里的椭圆轮廓远不止三个：工位环本身有内外两圈边缘，台面上还有别的圆形结构件。
所以不假设"最大的三个就是工位"，而是**先攒候选、再穷举组合、最后按几何打分**：

1. ``extract_observations``：``Canny → findContours(RETR_LIST) → fitEllipse``，
   按长短轴与扁平度过滤成"观测"。
2. ``cluster_observations``：并查集把圆心挨得近的观测并成一个**候选环**。
3. ``select_triple``：穷举三环组合，按共线度 / 间距均衡 / 直径一致 / 支撑数打分。

用 ``RETR_LIST`` 而不是 ``RETR_EXTERNAL`` 是有意的：环的内圈是一条**独立的**轮廓，
取外部轮廓会把内外两圈丢掉一圈，而"多圈支撑"正是把真环和杂项分开的主要依据。

### 候选环的两条支撑条件

| 条件 | 默认 | 为什么 |
|---|---|---|
| 观测条数 ``min_cluster_support`` | 4 | 一个真环的内外边缘会给出好几条椭圆 |
| 不同直径带 ``min_diameter_bands`` | 2 | **这一条才是真正管用的** |

第二条值得单独说：同一条边缘被 Canny 断成几截，会产生一堆**直径相同**的碎片——
条数够了，但直径带只有 1 个。没有这一条，画面里随便一段弧都会变成"候选环"。

### 中间那个环为什么不能只按"共线残差"挑

三个环本来就近似共线，此时**三个残差都是 0**。只按残差取最小，谁先被遍历到谁就成了
"中间"，顺序随机——实测就是这样把一个端点当成了中间环，间距比算出来是 **2.0**。

真正的判据是**投影位置**：中间环在两端连线上的投影必须落在中段（0.2–0.8），
端点会落在 0 或 1 附近。先按这一条筛，再在合格的里面取残差最小的。

### 圆心取"中位直径那条观测"，不取平均

一个候选环由好几条观测并成，它们的圆心本来就差一点点（内外两圈边缘）。
取平均会把圆心拽向"谁都不是"的位置——实测合成三环里被拽偏 **0.9 px**，
倾斜摆放时毫米偏差报成 **10 mm**（真值 0）。

所以取**中位直径那一条观测**的圆心与直径：两者来自同一次拟合，自洽。

### 偏角与偏差

- **工位偏角**：从环 1 圆心指向环 3 圆心的方向角。取 1→3 而不是 1→2，
  是因为两端离得最远、同样的像素噪声摊到角度上最小。
- **符号**：画面右方为 0、**下方为正**（y 轴向下），与两点测量同一套符号。
- **偏差**：三个环的实测圆心相对参考圆心的位移。验收卡的是**三环里最大的那个**——
  "有一个环偏得多"和"整体偏得多"是两回事。

### 验收要过的五道门

``within_tolerance`` 要求**全部**通过，少一道都不算：

| 门 | 配置项 | 默认 |
|---|---|---|
| 置信度 | ``minimum_confidence`` | 0.9 |
| 共线度残差 | ``maximum_affine_residual`` | 0.35 |
| 间距比 ``d12/d23`` | ``perspective_ratio_range`` | [0.85, 1.15] |
| 最大位移 | ``maximum_position_error_mm`` | 2.0 mm |
| 偏角误差 | ``maximum_angle_error_deg`` | 1.0° |

**没配比例尺时 ``within_tolerance`` 恒为 ``False``**：那时连毫米都没算出来，
"在容差内"这个结论无从谈起。同理，毫米字段是 ``None`` 而**不是 0**——
0 看起来像一个"完全对准了"的读数。

## 二、环心：给机械臂一个能直接对准的坐标

三圆环检测回答"工位摆正了没有"，但它给的是**像素圆心**与**相对参考的偏差**
（``error_x_mm`` 是差量）。机械臂要的是**位置**：这个环的圆心现在在相机系的哪一点。

:mod:`modules.vision.drive.numbered_ring` 补的就是这一层，两种取景各一个入口：

| 取景 | 入口 | 说明 |
|---|---|---|
| **窄视野，一次只有一个环**（相机装臂上时的常态） | ``Vision.locate_ring()`` / ``Vision.ring_center()`` | 只挑画面里那一个环，给环心 |
| 宽视野，三个环同时在画面里 | ``Vision.detect_numbered_rings()`` / ``ring_reading(digit)`` | 按左右顺序贴数字，给第 N 号环的环心 |

两者共用同一套坐标与墨迹判据：

```
环心像素 → 相机系毫米： (x - 宽/2) × station.mm_per_px ，y 同理（y 向下）
```

与 ``RegionReport.x_mm / y_mm`` **同一套坐标**（原点在光轴、x 右、y 下），所以可以直接喂
``align_xy(reading=...)``。

### 窄视野：一次只看到一个环（菜单 26）

相机装在臂上、镜头离纸很近时，画面里通常只有一个环。"同时看到三个"在这种取景下
**必然失败**，而"只看到一个环"本来就不是错误——所以单环路径不做"选出三个"，只做：

1. ``extract_observations`` + ``cluster_observations``（与三圆环同一套候选）；
2. 按"**圆心在画面内** > 支撑观测数 > 直径带数 > 离光轴近"排序，取第一个；
3. 环心 → 相机系毫米；环心内圆做墨迹核验（见下）。

两条与三圆环路径**不同**的取舍：

- **尺寸上限跟着画面走**：``station.max_major_axis_px``（默认 320）是按"整排三个 95 mm 环"
  定的，会把占满画面的单环当成杂项丢掉。单环路径把上限抬到画面短边——完整可见的环，
  直径不可能超过它。
- **圆心在画面外的候选排在后面**：画面边缘常常露出**隔壁环**的一段弧，它也能凑成一个
  "候选环"，但圆心是外推的。先选圆心在画面内的，避免对准到隔壁去。

半露的环仍然会给读数（``partial=True``）：机械臂离得远时，这是唯一能拿到的方向信息；
但它是**外推**的，调用方应当知道这一点。

### 为什么还要验一遍"环里有没有数字"

视野里那个环可能是**空环**（换纸、还没摆好）。空环的圆心照样能算出来，但机械臂可能
只是要跟住那个圆圈——所以单环路径**照常给坐标**，只把 ``digit_present=False`` 如实标出来，
由调用方决定收不收。宽视野那条路径更严：指定了第 N 号环却没有数字就返回 ``None``。

判据（``config.json`` 的 ``ring_digits`` 块）：

| 判据 | 默认 | 说明 |
|---|---|---|
| 内圆半径 | 环半径 × ``inner_ratio`` | 0.55，取太大就把环的虚线算成数字 |
| 墨迹阈值 | 灰度 < ``threshold`` | 100（白纸黑字） |
| 墨迹占比 | ``ink_ratio_range`` | [0.02, 0.40]，低于下限是空白、高于上限是整片阴影 |
| 字形高度 | ``min_glyph_ratio`` | 0.25（有墨迹的行数 / 内圆直径） |

### 数字靠顺序，不靠认字（宽视野那条路径）

环纸上的数字是**物理约定**（现场：左 1、中 2、右 3，2026-10-20 确认），朝向固定。
认字只会引入一类新的失败模式，而且认错了没法当场看出来——所以三个环同时可见时，
数字跟着左右顺序走，顺序在 ``ring_digits.order`` 里，换纸就改这一个字段。

**单环视野下顺序没有意义**（不知道它是第几个），所以单环路径不给号，只给环心与
"有没有数字"。

### 用法

```python
# 窄视野：一次一个环
centre = vision.ring_center()            # 相机系 (x_mm, y_mm)
if centre is not None:
    robot.grasp.align_xy(reading=centre)

target = vision.locate_ring()            # 需要更多信息时（半径、支撑、有没有数字）
if target is not None and target.usable:
    print(target.summary(), target.reading())

# 宽视野：三个环都在画面里
rings = vision.detect_numbered_rings()
target = vision.ring_reading(2)
```

返回 ``None`` 的情况：画面里没有环 / 没配比例尺（``station.mm_per_px``）；宽视野那条
还有"那个环里没有数字"。**不回退**到别的环——拿错一个环去对准，机械臂会朝 95 mm 外的
位置动，而动作看起来完全正常。

### 比例尺：已知直径 > 针孔标定 > 配置固定值

| 优先级 | 来源 | 条件 |
|---|---|---|
| 1 | **最内圈直径**：``毫米/像素 = ring_target.diameter_mm / 最内圈像素直径`` | 配了直径（现场 53 mm） |
| 2 | ``table_depth_mm / focal_px`` | 做过菜单 25 的标定 |
| 3 | ``station.mm_per_px`` | 兜底 |
| — | 都没有 | 不报毫米（``None``），不拿焦距凑 |

**为什么用最内圈**：一圈圆会给出**一组同直径**的观测（内外两道边 + 断续的虚线段），
而数字的轮廓虽然也会被 ``fitEllipse`` 拟成"圆"，却只有单独一条。所以"至少有两条观测
的直径带"才算"一圈圆"，再取其中最内的那个当基准——字迹因此被剔掉。

``RingTarget.band_diameters_px`` 里列出了本帧所有直径带，``summary()`` 会打印基准圈
的像素直径与比例尺来源；现场对着 53 mm 核一下就知道选中的是不是最内圈。

### 真机入口

菜单 26；也可以直接跑一张图（不需要摄像头、不加载模型）：

## 三、叠放位识别

找的是**一个中环 + 上下两条基准线**，靠线的倾角定方向（三圆环靠三点共线）。
两者判据没有一处共用，所以是两个检测器。

### 中环怎么找

1. 在参考圆心附近的窗口里 ``HoughCircles`` 出候选；
2. 对每个候选量 ``edge_support``——**圆周上有多少比例的角度真的落在边缘上**；
3. 取支撑率最高且过门槛的那个。

**为什么不直接信霍夫的票数**：霍夫对同一个环的内外两条边会各投一次，票数高不代表
这个圆真的贴合边缘；而支撑率是拿检测到的圆去**回头验**，这是"像不像一个环"的直接读数。

### 两条基准线

在环心上下各 ``line_offset_mm``（默认 75 mm）处，取一个带，对带内边缘点做
``cv2.fitLine(DIST_HUBER)`` 拟合。用 ``DIST_HUBER`` 而不是默认的 ``DIST_L2``：
带内总会混进别的边缘（物料轮廓、台面纹理），L2 会被它们拽偏，Huber 只让它们有一点发言权。

两条线本该平行，所以：

- 两条都找到 → 偏角取**两条线倾角的平均**，单条线的角度噪声被摊掉一半；
- 夹角超过 ``max_line_disagreement_deg``（默认 2°）→ 结论里写明"偏角不可信"，
  置信度**打五折**；
- 只找到一条 → 偏角仍然给出来，但 ``line_quality`` 是 0.5（两条平行线是 1.0）。

**线质量永远不比"只有一条线"更差**：两个线不平行时"至少找到了一条线"这个事实并没有
变坏。表达"夹角太大所以不可信"的地方是置信度，不是质量——一个指标同时承担
"有多少证据"和"证据有多可信"两件事，调用方就没法从它读出"是不是只看到一条线"了。

### 毫米换算：尺度从哪来

``line_offset_mm`` 是毫米，要落到画面上得先有比例尺。优先级：

| 来源 | ``scale_source`` | 可信 |
|---|---|---|
| ``station.image_to_station_affine`` 的竖直尺度 | ``"affine"`` | 是 |
| ``station.mm_per_px`` | ``"mm_per_px"`` | 是 |
| 用中环半径按"外径 95 mm"反推 | ``"ring"`` | **否** |
| 都没有 | ``"none"`` | — |

从环反推的那一条只为了在没标定的机器上也能跑起来看画面对不对。
结果的 ``scale_trustworthy`` 会写成 ``False``，毫米读数只能当参考。

## 四、两点像素测量

### 为什么不用 OpenCV 的测量原语

没有这样的原语。``cv2.arcLength`` 量的是轮廓周长，``cv2.norm`` 量的是向量模长但拿不到
有符号分量。这条链路本来就只有 ``dx``、``dy``、``hypot`` 三个式子。

### 符号是主输出

``dx_px = end.x - start.x``，**不排序、不取绝对值**。第一击与第二击的顺序决定正负号，
而正负号在"判断工件偏左还是偏右"时就是结论本身——给反了就得到反的符号，这是如实报数。

调用方写法不对时**当场报错**（``ValueError``），不静默补 0：
少点了一下会变成"量出左边缘到另一点的距离"，那种错误在现场表现为一个看起来正常的数。

### 画面冻结

不冻结的话，从第一次点击到第二次点击之间画面一直在动，两次点击量的就不是同一个场景里的
两个点，读数没有意义。所以：**0 个点（实时）→ 1 个点（冻结）→ 2 个点（冻结）→ 第三次点击清空**。

### 毫米换算

``毫米 = 像素 × 工作距离 / 焦距``。``working_distance_mm`` 是**被测平面**到镜头的距离；
用错这个数（例如拿台面深度去量一个抬高的工件顶面）会按比例整体缩放结果，而
**方向与比值不受影响**——所以"偏左还是偏右"永远可信，"偏了几毫米"取决于这个数。

## 五、停稳门控：静止不等于停稳

### 它补的是哪个洞

``Fusion.moving`` 回答的是"这一批连拍里读数有没有系统性漂移"。它答不了另一个问题：

> 转盘**本来就静止**时，读数连续几帧一模一样——看起来和"转完停稳了"完全一致。

把这两种情况混为一谈，现场表现就是**上一轮的残留状态被当成这一轮的结果上报**：
转盘还没开始转，上报已经发出去了。这不是精度问题，是逻辑错误，而且它只在
"刚好赶上静止的那一瞬间"才复现，最难查。

所以门控把"动过"变成一个**必须显式观察到的事实**，而不是从"现在很静"反推出来的结论。

### 判据

| 阶段 | 条件 | 默认 |
|---|---|---|
| 动过 | 连续若干帧速度 ≥ ``moving_speed_px_s`` | 30 px/s，2 帧 |
| 停稳 | 动过之后，连续若干帧速度 ≤ ``near_stop_speed_px_s`` | 25 px/s，3 帧 |
| 上报 | 停稳的那一刻，**一个周期只发一次** | — |

两个阈值差一截（30 对 25）是刻意的：**迟滞**让"33→28→32 px/s"这种在阈值上抖动的读数
不会把状态机来回翻面。

### 三条刻意的取舍

- **漏检不撤销"动过"**：速度算不出来、测速基准被重建，但"转过"是一个已经发生过的事实，
  不该因为后来漏了两帧就被撤销。
- **只有 ``reset()`` 能清掉"动过"**：别的路径都不清。
- **跨了掉帧的间隔算不出速度**：与其拿一段跨了掉帧的间隔去算平均速度
  （会把"绕着走了一大圈又回来"当成"没动"），不如少算一次。

### 会话里怎么用

```python
fused = vision.measure_settled(require_motion=True)   # 没看见转过就一直等到超时
```

**单位提醒**：门控的阈值默认按**像素/秒**给（它本来就是为画面位移设计的）。
走 ``Vision.measure_settled`` 这条路径时喂进去的是**毫米**（``TimedPoint`` 不带像素坐标），
所以那里用的是 ``DEFAULT_SETTLED_MOTION_MM_S = (30.0, 25.0)`` 这两个按毫米定的默认值。
刻意**不做**毫米↔像素的自动换算：那需要焦距，而焦距标定目前还是粗标定值，
拿它去换单位等于把一个不确定的数引进"动没动"这个判断里。

## 六、标定：焦距与台面深度（菜单 25）

``modules/vision/calibration.json`` 里 ``focal_px``、``table_depth_mm``、``plane``
原本全是 ``null``，所以所有毫米读数用的都是粗标定兜底值，**不是真实距离**。

菜单 25 补前两项：

1. 把一块**已知直径的圆片**平放在台面上、离镜头已知距离处，尽量正对镜头；
2. 按 ``f`` 进入焦距标定，左键点圆片**左边缘**、再点**右边缘**；
3. 终端会问真实直径与到镜头的距离，工具反解出焦距；
4. 多测几次更稳，按 ``s`` 保存平均值；按 ``d`` 直接设置台面深度；按 ``c`` 看还缺什么。

反解公式 ``f = 距离 × 像素直径 / 真实直径``，与
``modules.vision.drive.pixel_measure.focal_px_from_known_length`` 同一处实现。

**只写 ``calibration.json``，不碰 ``config.json``**：两者生命周期不同，
标定产物不该顺手改动手改的配置。

## 七、配置速查

两个块都在 ``modules/vision/config.json``。**所有判据都在配置里，换工位不用改代码。**

### ``station`` 块

| 分组 | 字段 |
|---|---|
| 真实尺寸与换算 | ``center_spacing_mm``、``outer_diameter_mm``、``ring1_side``、``mm_per_px``、``image_to_station_affine`` |
| 检测阈值 | ``canny_low``、``canny_high``、``min_contour_points``、``min_minor_axis_px``、``max_major_axis_px``、``min_ellipse_aspect``、``center_cluster_radius_px``、``diameter_band_gap_px``、``min_cluster_support``、``min_diameter_bands``、``min_station_span_ratio``、``max_collinearity_error_ratio`` |
| 参考与验收 | ``station_yaw_deg``、``ring_centers_px``、``minimum_confidence``、``stable_frame_count``、``maximum_center_jitter_px``、``maximum_affine_residual``、``perspective_ratio_range``、``maximum_position_error_mm``、``maximum_angle_error_deg`` |

``ring1_side`` 决定哪一端算环 1（``"left"`` / ``"right"``）。工位翻面装时改这一个字段。

### ``stacked_ring`` 块

``middle_min_radius_px``、``middle_max_radius_px``、``middle_edge_support``、
``middle_search_radius_px``、``middle_reference_px``、``middle_max_reference_distance_px``、
``line_offset_mm``、``max_line_angle_deg``、``max_line_disagreement_deg``、
``min_line_points``、``min_line_x_span_px``、``minimum_confidence``、
``stable_frame_count``、``maximum_center_jitter_px``。

叠放位的**比例尺复用 ``station`` 块**，不在 ``stacked_ring`` 里再配一份：
同一台机器只该有一个比例尺。

### ``ring_digits`` 块

| 字段 | 默认 | 管什么 |
|---|---|---|
| ``order`` | ``[1, 2, 3]`` | 左→右的数字顺序；换纸/翻面只改这个 |
| ``inner_ratio`` | 0.55 | 环心内圆半径 = 环半径 × 它 |
| ``threshold`` | 100.0 | 低于它的灰度算墨迹 |
| ``ink_ratio_range`` | ``[0.02, 0.40]`` | 内圆里墨迹占比的合理区间 |
| ``min_glyph_ratio`` | 0.25 | 字形高度占内圆直径的比例下限 |

### ``ring_target`` 块

| 字段 | 默认 | 管什么 |
|---|---|---|
| ``diameter_mm`` | 53.0 | **最内圈**的真实直径（毫米）；比例尺按它算，``null`` 则退回针孔/固定比例尺 |
