# 视觉物料定位：顶部圆面与 30 mm 测距

## 判定流程

定位器有两种，``MaterialLocator`` 按有没有配物料颜色自动选：

- **配了 ``targets.material_palette``（推荐）**：``modules.vision.drive.material_blob.ColourBlobLocator``
  按参考颜色分割 → 连通域 → 轮廓 → **拟合圆**（``modules.vision.drive.circle_fit``）给出圆心与半径。
  夹爪、台面、线材、结构件根本进不了掩膜，所以既不会把夹爪当物料，也不会在几十个候选里挑错圆。
  拟合不可信时退回「质心 + 面积等效半径 ``sqrt(area/π)``」，见下面《圆心与半径为什么必须拟合》。
- **没配颜色**：``modules.vision.drive.hough_lock.HoughRingLocator`` 走霍夫圆，
  再用 ``modules.vision.drive.material_face.measure_face`` 判"像不像顶面"
  （内部灰度标准差 + 圆周边缘支撑）。颜色未知时只能这样，但近距机位下夹爪圆弧
  与顶面尺度相近，误判/漏判都明显更多。

### 调色板：换一块料不必改代码

物料有六种颜色，参考色天生是个**调色板**，写在 ``config.json``：

```json
"targets": {
  "material_palette": {
    "green": [165.0, 252.0, 114.0],
    "blue":  [248.0, 122.0, 41.0],
    "red":   [49.0, 80.0, 255.0],
    "yellow":[74.0, 198.0, 246.0]
  }
}
```

菜单 18 也可以用 ``--palette "green:165,252,114;blue:248,122,41"`` 临时覆盖。

**没配的颜色也能认**：调色板一个色块都没找到时，程序去问模型；模型认出来了，就从它那个框
的中心取一次参考色，再用这个参考色分割一遍（报告里 ``colour_source="model"``，
``summary()`` 会写明"参考色是从模型框里现取的"）。所以换料不必先量颜色——把它加进调色板
只是让"模型没认出来时"也能用，以及让 `best` 的类别更稳。

模型也没认出来，才退回霍夫的形状判据（``colour_source="hough"``，旧字段
``colour_fallback=True``）。这时误判/漏判都会明显变多，``summary()`` 会提示把颜色补进调色板。

### 颜色匹配为什么不能只看 BGR

参考色是在**某一盏灯下**取的。实测同一块绿料在两种光照下是 ``(165,252,114)`` 与
``(130,204,48)``：BGR 欧氏距离 88，早就超出容差 60——于是"挪了下机位就识别不到"。
但这两次读数的**色相只差 5**（71 与 76），而深绿台面差 14 以上。

所以匹配是「**色相 ±10** 或 **BGR 距离 ≤ 60**」，外加**亮度下限**（V ≥ 参考色 V 的 0.65 倍，
台面与物料色相接近、差的就是明暗：实测 V 85 对 204–252）。参考色取在阴影里也不怕——
匹配只看色相和亮度下限，亮起来的同一块料照样命中。

### 同色的结构件怎么排除

调色板里有蓝色，画面里的蓝色 3D 打印件也会命中同一个颜色，靠颜色分不开。但物料顶面是个**圆**，
所以再加两道只看形状的检查（``ColourBlobLocator``）：

| 检查 | 物料实测 | 同色打印件实测 |
|---|---|---|
| 边界起伏（轮廓点到形心距离的变异系数） | 0.02–0.31 | 0.38–0.51 |
| 填充率（等效半径 / 外接圆半径） | 0.74–0.96 | 0.36–0.53 |

边界起伏只对**完整入画**的色块有效（贴着画面边缘、或者顶面一半落在阴影里时，
掩膜边界本来就是歪的），这些情况靠填充率兜住。注意：**正方形**在这个指标上其实
很接近圆（实测 0.12），真正分得开的是打印件那种带缺口/台阶的异形件。

无论哪条路，最终都用固定的顶部圆面直径（默认 30 mm，读 ``targets.material_diameter_mm``）
按针孔模型换算距离；YOLO 只补充类别。

``MaterialReport`` 的取用：

- ``regions``：所有候选（诊断用，可能包含被丢掉的夹爪圆弧）。
- ``faces`` / ``rejected``：通过校验的顶面 / 被丢掉的候选。
- ``best``：YOLO 认出类别时取置信度最高的；否则取**半径最大的已通过顶面**（同一个
  顶面常被凑出大小两个同心圆，小的那个会把距离报远）；一个都没有就是 ``None``，
  下游不要拿旧值继续算逆解。
- ``radius_window_px``：这一帧实际用的半径窗口，排查先看它。

`modules.vision.drive.material_presence` 与 `modules.vision.drive.material_distance` 是基于 YOLO 框的独立辅助模块，不参与这个主流程。

## 工作距离先验

半径窗口默认按画幅猜（如 1280×720 下 26–259 px），这在**相机离物料很近**时不够用：
物料顶面变得很大，而夹爪圆弧、背景平坦区也能凑出同样尺度的圆。先验就是把「相机装多高」
写进 `modules/vision/config.json`：

```json
"targets": { "working_distance_mm": [55.0, 160.0] }
```

每一帧的半径窗口由针孔模型算出（近端给大半径）：`r = focal_px × 直径 / (2 × 深度)`。
菜单 18 与 `python -m modules.vision.drive.material_locate` 都接受 `--depth 60,85` 覆盖它；
`MaterialLocator(depth_range_mm=(55.0, 160.0))` 是程序里的入口。没配时行为与以前完全一致。
**范围要覆盖你真正会用的距离区间**：物料可能落在夹爪下方 4–5 cm，那就要把远端放到 15 cm 以上，
否则会被窗口直接筛掉（这就是"物块在爪子下面一点就识别不到"的原因）。

> **画面发虚时霍夫那一路基本不可用。** 近距离焦时圆边梯度被摊平，霍夫默认 Canny 高阈值 100
> 只会留下夹爪那种高对比弧线，锁到半径偏大的假圆（实测 248 px / 61 mm，真值 218 px / 70 mm）。
> `MaterialLocator` 会在严格参数没找到顶面时自动用 `HoughRingLocator.relaxed()`（阈值 50）再试一次，
> 但真正稳的是配颜色走颜色块那一路。

## 实测对照（同一台机器，1280×720，焦距按 1012 px 粗标定，顶面按 30 mm）

| 画面 | 霍夫 + 形状判据 | 颜色块 | 卷尺 |
|---|---|---|---|
| 7 cm 机位（物料夹在爪里） | 70.1 mm，但候选里有 2–3 个夹爪圆弧 | 71.0 mm | ≈70 mm |
| 12 cm 机位（物料在爪下方） | 98–113 mm 或直接漏检；36–44 个候选 | **125.8 mm** | ≈120 mm |
| 12 cm，连续 10 帧 | 距离读数会跳 | **125.8 mm ± 0.16 mm** | — |
| 换成蓝色物料后 | 需要重调参数 | **107.7 mm ± 0.15 mm**，1 个候选 | — |

颜色块那一路还顺带把类别救回来了：新导出的 320×320 四分类模型（``red/yellow/blue/green``）
在这套画面里给出 ``green 0.94``，而旧的 640×640 十分类模型是 0 个框。

## 距离与标定

`distance_mm = focal_px × 30 / (2 × radius_px)`。

对每个圆面，还按相机坐标系估算位置：`x_mm = (center_x_px - width/2) × z_mm / focal_px`，`y_mm = (center_y_px - height/2) × z_mm / focal_px`，`z_mm = distance_mm`。x 向画面右、y 向画面下、z 沿镜头向前；`range_mm = √(x_mm² + y_mm² + z_mm²)` 是圆面中心到相机的空间直线距离。这里近似认为主点在画面中心、水平与竖直像素焦距相等，尚未校正镜头畸变。

距离的绝对精度取决于两件事，两个都要自己量一次：

- **顶部圆面的真实直径**。代码按 30 mm 算；实测 7 cm 机位下顶面 433 px，正好对应 70 mm，与卷尺一致。直径若其实是 39 mm，所有距离都会小 30%。
- **像素焦距** `focal_px`。默认 1012 px 来自一张"约 145 mm"的照片，是粗标定；按 `focal_px = 已知距离 × 圆面像素直径 / 30` 在自己机位上重标一次即可（见 `modules/grasp/docs/抓取坐标链路.md` 实验 A′）。

半径每差 1 px，70 mm 处就差约 0.3 mm；所以判据选错圆的代价（十几到几十毫米）远大于标定误差，先验 + 顶面判据要一起用。

`models/top_pic_2.jpg` 是 1280×720 原图，内侧圆面直径约 209 px。拍摄时从镜头到圆面约 145 mm，且没有数码变焦，可反推该画幅的像素焦距约 `145 × 209 / 30 = 1012 px`。实测距离是约数，因此这是一次粗标定。

默认焦距只接受未裁切的 16:9 画幅，并按实际帧宽度从 1280 px 等比例换算。其他画幅须显式传入该画幅标定后的 `focal_px`；裁切或变焦不同也应重新标定。距离指镜头到物料顶部平面，不是机械臂末端距离。相机畸变和物料倾斜也会带来误差。

## 使用与验收

其他模块直接传入一帧原始 BGR 图像即可；检测器应在连续处理帧时复用：

```python
from modules.vision.drive.material_locate import MaterialLocator

with MaterialLocator() as locator:
    report = locator.locate(frame)
    if report.present:
        for item in report.regions:
            print(item.name, item.confidence)
            print(item.center_x_px, item.center_y_px)
            print(item.x_mm, item.y_mm, item.z_mm, item.range_mm)
```

只跑一帧图像的离线工具从 `modules.vision.drive.material_locate` 导入；
**要连相机、连模型一起用**的上层代码请走会话接口，它负责打开 / 关闭设备：

```python
from modules.vision import Vision

with Vision.open(config_path="modules/vision/config.json") as vision:
    report = vision.locate()
```

`report.present` 由霍夫圆面决定。`item.confidence` 是 YOLO 类别分数，不是校准过的真实概率；YOLO 漏检时 `item.name` 和 `item.confidence` 均为 `None`，圆心与三维估算仍保留。`item.distance_mm` 与 `item.z_mm` 同义。相机坐标不是机械臂坐标，机械臂使用前需要另行标定相机与机械臂的相对位姿。

下游只该拿 `report.best`，不要自己取 `report.regions[0]`：圆面是按 x 排序的，第一个不一定是物料。`report.best` 可能是 `None`（没锁到顶面），这时不要拿旧值继续算逆解。`report.faces` 是"像顶面"的子集，`report.radius_window_px` 是这一帧实际用的窗口，排查时先看这两个。

## 光照一差就认不出：每一道门槛改哪里

一个色块要变成 `report.best`，要按顺序过下面这些门。**它们现在全部在 `modules/vision/config.json`
的 `targets` 块里**（早先写死在 `material_blob` / `material_face` 的常量里，现场只能改代码）：

| 门槛 | 配置键 | 现在 | 放宽会怎样 |
|---|---|---|---|
| BGR 距离容差 | `color_tolerance` | 60 | 直接放宽；同色结构件也更容易进来 |
| 色相容差（换了灯仍认得出） | `hue_tolerance` | 10 | **别超过 12**：台面色相离绿料只差 14 |
| 亮度下限（V ≥ 参考 V × 比值） | `value_ratio` | 0.65 | **别低于 0.42**：台面 V≈85、物料 V≈204–252 |
| 色块最小面积 | `min_area_px` | 500 | 调小能救小块/远块，噪点也更容易进来 |
| 边界起伏上限 | `max_boundary_variation` | 0.35 | `null` = 不查这一项（同色结构件会更难排除） |
| 填充率下限 | `min_fill_ratio` | 0.65 | `null` = 不查这一项 |
| 内部灰度标准差上限 | `interior_std_max` | 12.0 | 光照不均时真顶面会到 15–20，抬高它最直接 |
| 圆周边界支撑下限 | `edge_support_min` | 0.55 | 调低能救边缘模糊的块，背景平地也更容易混进来 |
| 严格容差找不到时的第二遍倍数 | `colour_relax_factor` | 1.5 | **只放大 BGR 容差**；`1.0` = 不放松 |
| 工作距离窗口（半径窗口的出处） | `working_distance_mm` | [55,160] | 高度不对时**整块料被直接丢弃**，先查这一项 |
| YOLO 置信度阈值 | `model.conf_thresh` | 0.25 | 调低让模型多出框——**有框就能救活一个形状不达标的色块** |

**放松档（`colour_relax_factor`）**：严格 BGR 容差一个色块都没找到时，按这个倍数再分割一遍，
并把报告里的 `colour_source` 标成 `"palette-relaxed"`（`MaterialReport.summary()` 会写一行说明）。
它**只放大 BGR 容差**：色相与亮度下限原样带过去，因为那两个阈值是拿台面实测定的，一放台面就整片进掩膜。
代价是"什么都没找到"的那一帧要多跑一遍颜色分割——找到料的那一帧行为与开销都不变。

现场调参用根目录的实时预览（**只看不动**，不开机械臂）：

```powershell
python test_vision.py                      # 实时预览：绿粗圈=接受、灰细圈=丢掉并写明没过的判据
python test_vision.py --std-max 18         # 只覆盖这一次：抬高内部标准差上限
python test_vision.py --tolerance 90 --min-area 300
python test_vision.py --once               # 只跑一帧，把每个候选的判据数字打到终端
```

命令行覆盖**不写回文件**；找到合适的值再手工写进 `config.json`（每一项的代价就是上表那一列）。

> 两条不属于配置、但现场最值钱的事：**光**（顶面反光会让色块被高光切成两块）和
> **参考色**（换灯之后对着物料重新取一次顶面中位数，比调容差有效得多）。

## 圆心与半径为什么必须拟合，而不是取质心和面积

顶面被夹爪挡掉一角、或者一半落进阴影里时，掩膜只剩**残缺的圆**：

- **连通域质心**被拽向可见的那一半 → 圆心偏，``x_mm`` / ``y_mm`` 跟着偏；
- **面积等效半径** ``sqrt(area/π)`` 比真实半径小 → ``z`` 报远。

两个数一起错，而流程**照样接受**这个候选，把错的数交给逆解——这比"没找到"更危险。
所以圆心与半径现在取 ``modules.vision.drive.circle_fit`` 的 **Kåsa 代数最小二乘 + RANSAC**
结果：只让"同意同一个圆"的点说话，遮挡留下的那条**直边（弦）**被当成外点。

实测（真机帧 ``output/vision_predict/material_locate_live.png``，真值半径 145.4 px，
从左侧推进一块不属于任何调色板颜色的遮挡）:

| 顶面被挡 | 面积等效半径 | 距离误差 | 拟合半径 | 距离误差 |
|---|---|---|---|---|
| 0% | 144.6 | +0.6 mm | 146.4 | −0.7 mm |
| 15% | 136.9 | +6.5 mm | 146.0 | −0.4 mm |
| 30% | 124.8 | **+17.2 mm** | 145.6 | −0.1 mm |
| 45% | 108.2 | **+35.9 mm** | 145.1 | +0.2 mm |

拟合不可信时（点太少、解跑到半径窗口外、内点占比或角度覆盖太低）自动退回原来的估计，
**所以定位器不会因为多了这一步而更容易漏检**。半径窗口在这里当"合理域"用：退化样本会
给出 r=1739 这类解，内点数甚至比真解还多，只有半径域能一眼挡掉。

### 怎么判断这一帧的圆心可不可信：把圆和 YOLO 框摆在一起看

顶面是个圆，模型框得紧的时候 ``(宽 + 高) / 4`` 就是半径的另一个独立估计。实测：

| 帧 | 圆拟合半径 | YOLO 框 → 半径 | 差 |
|---|---|---|---|
| ``material_locate_live.png`` | 146.4 px | 294×294 → 147.0 px | **+0.6 px** |
| ``top_pic_2.jpg`` | 131.5 px | 269×262 → 132.9 px | **+1.4 px** |
| ``now.png`` | 126.7 px | 401×439 → 210.1 px | +83.4 px（松框，别信） |
| ``p0_before.png`` | 143.8 px | 395×371 → 191.6 px | +47.8 px（松框，别信） |

**框紧的时候两者互相印证；框松的时候（模型把台面/夹爪一起框进去了）只该信圆。**
`python test_vision.py` 的终端输出会把这一行并排打出来，实时预览里也能直接比绿圈和黄框。

> **不要**改成"拿 YOLO 框中心当物料中心"：实测 8 张真机帧，**框中心比色块质心更接近
> 拟合圆心的只有 3 张**（其中两张只近 1–2 px，基本是平手），另外 5 张质心更近，
> 最差的一帧是 58.5 px 对 8.7 px（``p2_return.png``）。框紧时它和**拟合圆心**
> 本来就是一回事（上表差 0.6 / 1.4 / 0.0 px），框松时它没有意义——拟合圆才是
> "框紧时等于框中心、框松时仍然对"的那个估计。

### 放松档是候补，不是结论

``colour_relax_factor`` 那一遍的候选**只在模型也没辙时**才上场。原因是实测
``models/top_pic_2.jpg``：BGR 容差 60→90 之后，先捞到的其实是左上角一块台面
（r=197 px，正好落在半径窗口里）；它一旦成为结论，下面就再也不会去问模型，
而那块蓝料明明被模型框到 0.96。现在候补排在"模型现取参考色"之后、霍夫之前。

## 物料会动：多帧融合（`Vision.measure`）

上面讲的全是**一帧**。物料放在转盘上（会转、会停）时单帧不够用：

- 运动模糊会让某一帧整个检不到，或者把圆的直径拉长、把 z 报错；
- "现在到底停稳了没有"是单帧回答不了的问题。

所以 ``Vision`` 多了两个多帧接口：

```python
with Vision.open() as vision:
    fused = vision.measure()                  # 连拍 7 帧，稳健融合成一个值
    if fused is not None:
        print(fused.point.x_mm, fused.point.y_mm, fused.point.z_mm)
        print(fused.moving, fused.speed_mm_s, fused.spread_mm)

    settled = vision.measure_settled()         # 反复拍，直到停稳（或超时）
```

命令行上：

```powershell
python test_vision.py --measure               # 连拍 7 帧，打印融合结论与退出码
python test_vision.py --measure --frames 12   # 多拍几帧
python test_vision.py --measure --settle      # 拍到停稳为止（超时 4 s）
```

退出码 ``0`` = 拿到一次可信测量，``1`` = 没拿到（有效读数不够 / 还在动），
可以直接当脚本判据。

### 为什么不能"取个平均"

单帧观测有两种**完全不同**的坏法，用同一套平均会两头不讨好：

| | 读数长什么样 | 取平均会怎样 | 正确做法 |
|---|---|---|---|
| **抖**（静态噪声） | 围着真值跳 | 还行，但野值会把它拖走 | 剔野值后取稳健中心 |
| **动**（系统性漂移） | 时间上单调地走 | 给出一个**哪一时刻都不是**的位置 | 报出速度和"还在动" |

更麻烦的是：对着一串**真值持续变化**的读数按"离中心太远"剔野值，会把**所有**帧
都剔掉——因为在动的时候，"离中心远"恰恰是正常的。

所以 ``modules.vision.drive.sequence.fuse`` 先拟合一条**时间上的直线**
（Theil–Sen 中位数斜率，一两个野值改不动它），再按"离这条线多远"剔野值：

- 静止时斜率≈0，这条线就是中心值，行为和普通稳健平均一样；
- 运动时斜率≠0，判据跟着线走，帧不会被误剔；``moving`` 为 ``True`` 并且给出速度。
  此时那个值是按速度**外推**到参考时刻的（默认参考时刻 = 最后一帧 = "现在"），
  要某一时刻的值就传 ``reference_stamp``。

**为什么可以用直线近似圆周运动**：转盘上的物料走的是圆弧，但一次融合只覆盖很短
一段时间（7 帧约 1.25 s），转盘在这段时间里只转过很小的角度，圆弧在一小段上与
直线无异。真要长时间跟踪圆周，该在外层做圆周拟合，而不是把窗口拉长。

### 结果怎么读

| 字段 | 含义 |
|---|---|
| `point` | 融合出来的观测（`stamp` 是参考时刻） |
| `moving` / `velocity_mm_s` / `speed_mm_s` | **还在动**这个结论本身，以及速度 |
| `spread_mm` | 内点相对融合值的最大偏差——"这一串读数有多一致" |
| `samples` / `rejected` / `misses` | 内点帧数 / 被剔掉的帧数 / 一帧都没看到的次数 |
| `colors` | 这一批出现过的颜色；多于一种说明**可能换了一个目标** |
| `confident` | 内点够多、没在动、且野值没过半 |

``measure()`` 返回 ``None`` 表示**有效读数不够（少于 3 帧看到物料）**——这时
不要退回单帧值，那正是这个接口要挡掉的东西。

``spread_mm`` 刻意**没有**写进 ``confident``：它的合理量级取决于距离与标定，
写死一个毫米数会在近处过严、远处过松。调用方拿它和自己的容差比。
