# 视觉物料定位：顶部圆面与 30 mm 测距

## 判定流程

定位器有两种，``MaterialLocator`` 按有没有配物料颜色自动选：

- **配了 ``targets.material_palette``（推荐）**：``modules.vision.drive.material_blob.ColourBlobLocator``
  按参考颜色分割 → 连通域 → **面积等效半径** ``sqrt(area/π)``。夹爪、台面、线材、
  结构件根本进不了掩膜，所以既不会把夹爪当物料，也不会在几十个候选里挑错圆。
- **没配颜色**：``modules.vision.drive.hough_lock.HoughRingLocator`` 走霍夫圆，
  再用 ``modules.vision.drive.material_face.measure_face`` 判"像不像顶面"
  （内部灰度标准差 + 圆周边缘支撑）。颜色未知时只能这样，但近距机位下夹爪圆弧
  与顶面尺度相近，误判/漏判都明显更多。

### 调色板：换一块料不必改代码

物料有六种颜色，参考色天生是个**调色板**，写在 ``config.json``：

```json
"targets": {
  "material_palette": {
    "green": [165.0, 252.0, 114.0],
    "blue":  [248.0, 122.0, 41.0],
    "red":   [49.0, 80.0, 255.0],
    "yellow":[74.0, 198.0, 246.0]
  }
}
```

菜单 18 也可以用 ``--palette "green:165,252,114;blue:248,122,41"`` 临时覆盖。

**没配的颜色也能认**：调色板一个色块都没找到时，程序去问模型；模型认出来了，就从它那个框
的中心取一次参考色，再用这个参考色分割一遍（报告里 ``colour_source="model"``，
``summary()`` 会写明"参考色是从模型框里现取的"）。所以换料不必先量颜色——把它加进调色板
只是让"模型没认出来时"也能用，以及让 `best` 的类别更稳。

模型也没认出来，才退回霍夫的形状判据（``colour_source="hough"``，旧字段
``colour_fallback=True``）。这时误判/漏判都会明显变多，``summary()`` 会提示把颜色补进调色板。

### 颜色匹配为什么不能只看 BGR

参考色是在**某一盏灯下**取的。实测同一块绿料在两种光照下是 ``(165,252,114)`` 与
``(130,204,48)``：BGR 欧氏距离 88，早就超出容差 60——于是"挪了下机位就识别不到"。
但这两次读数的**色相只差 5**（71 与 76），而深绿台面差 14 以上。

所以匹配是「**色相 ±10** 或 **BGR 距离 ≤ 60**」，外加**亮度下限**（V ≥ 参考色 V 的 0.65 倍，
台面与物料色相接近、差的就是明暗：实测 V 85 对 204–252）。参考色取在阴影里也不怕——
匹配只看色相和亮度下限，亮起来的同一块料照样命中。

### 同色的结构件怎么排除

调色板里有蓝色，画面里的蓝色 3D 打印件也会命中同一个颜色，靠颜色分不开。但物料顶面是个**圆**，
所以再加两道只看形状的检查（``ColourBlobLocator``）：

| 检查 | 物料实测 | 同色打印件实测 |
|---|---|---|
| 边界起伏（轮廓点到形心距离的变异系数） | 0.02–0.31 | 0.38–0.51 |
| 填充率（等效半径 / 外接圆半径） | 0.74–0.96 | 0.36–0.53 |

边界起伏只对**完整入画**的色块有效（贴着画面边缘、或者顶面一半落在阴影里时，
掩膜边界本来就是歪的），这些情况靠填充率兜住。注意：**正方形**在这个指标上其实
很接近圆（实测 0.12），真正分得开的是打印件那种带缺口/台阶的异形件。

无论哪条路，最终都用固定的顶部圆面直径（默认 30 mm，读 ``targets.material_diameter_mm``）
按针孔模型换算距离；YOLO 只补充类别。

``MaterialReport`` 的取用：

- ``regions``：所有候选（诊断用，可能包含被丢掉的夹爪圆弧）。
- ``faces`` / ``rejected``：通过校验的顶面 / 被丢掉的候选。
- ``best``：YOLO 认出类别时取置信度最高的；否则取**半径最大的已通过顶面**（同一个
  顶面常被凑出大小两个同心圆，小的那个会把距离报远）；一个都没有就是 ``None``，
  下游不要拿旧值继续算逆解。
- ``radius_window_px``：这一帧实际用的半径窗口，排查先看它。

`modules.vision.drive.material_presence` 与 `modules.vision.drive.material_distance` 是基于 YOLO 框的独立辅助模块，不参与这个主流程。

## 工作距离先验

半径窗口默认按画幅猜（如 1280×720 下 26–259 px），这在**相机离物料很近**时不够用：
物料顶面变得很大，而夹爪圆弧、背景平坦区也能凑出同样尺度的圆。先验就是把「相机装多高」
写进 `modules/vision/config.json`：

```json
"targets": { "working_distance_mm": [55.0, 160.0] }
```

每一帧的半径窗口由针孔模型算出（近端给大半径）：`r = focal_px × 直径 / (2 × 深度)`。
菜单 18 与 `python -m modules.vision.drive.material_locate` 都接受 `--depth 60,85` 覆盖它；
`MaterialLocator(depth_range_mm=(55.0, 160.0))` 是程序里的入口。没配时行为与以前完全一致。
**范围要覆盖你真正会用的距离区间**：物料可能落在夹爪下方 4–5 cm，那就要把远端放到 15 cm 以上，
否则会被窗口直接筛掉（这就是"物块在爪子下面一点就识别不到"的原因）。

> **画面发虚时霍夫那一路基本不可用。** 近距离焦时圆边梯度被摊平，霍夫默认 Canny 高阈值 100
> 只会留下夹爪那种高对比弧线，锁到半径偏大的假圆（实测 248 px / 61 mm，真值 218 px / 70 mm）。
> `MaterialLocator` 会在严格参数没找到顶面时自动用 `HoughRingLocator.relaxed()`（阈值 50）再试一次，
> 但真正稳的是配颜色走颜色块那一路。

## 实测对照（同一台机器，1280×720，焦距按 1012 px 粗标定，顶面按 30 mm）

| 画面 | 霍夫 + 形状判据 | 颜色块 | 卷尺 |
|---|---|---|---|
| 7 cm 机位（物料夹在爪里） | 70.1 mm，但候选里有 2–3 个夹爪圆弧 | 71.0 mm | ≈70 mm |
| 12 cm 机位（物料在爪下方） | 98–113 mm 或直接漏检；36–44 个候选 | **125.8 mm** | ≈120 mm |
| 12 cm，连续 10 帧 | 距离读数会跳 | **125.8 mm ± 0.16 mm** | — |
| 换成蓝色物料后 | 需要重调参数 | **107.7 mm ± 0.15 mm**，1 个候选 | — |

颜色块那一路还顺带把类别救回来了：新导出的 320×320 四分类模型（``red/yellow/blue/green``）
在这套画面里给出 ``green 0.94``，而旧的 640×640 十分类模型是 0 个框。

## 距离与标定

`distance_mm = focal_px × 30 / (2 × radius_px)`。

对每个圆面，还按相机坐标系估算位置：`x_mm = (center_x_px - width/2) × z_mm / focal_px`，`y_mm = (center_y_px - height/2) × z_mm / focal_px`，`z_mm = distance_mm`。x 向画面右、y 向画面下、z 沿镜头向前；`range_mm = √(x_mm² + y_mm² + z_mm²)` 是圆面中心到相机的空间直线距离。这里近似认为主点在画面中心、水平与竖直像素焦距相等，尚未校正镜头畸变。

距离的绝对精度取决于两件事，两个都要自己量一次：

- **顶部圆面的真实直径**。代码按 30 mm 算；实测 7 cm 机位下顶面 433 px，正好对应 70 mm，与卷尺一致。直径若其实是 39 mm，所有距离都会小 30%。
- **像素焦距** `focal_px`。默认 1012 px 来自一张"约 145 mm"的照片，是粗标定；按 `focal_px = 已知距离 × 圆面像素直径 / 30` 在自己机位上重标一次即可（见 `modules/grasp/docs/抓取坐标链路.md` 实验 A′）。

半径每差 1 px，70 mm 处就差约 0.3 mm；所以判据选错圆的代价（十几到几十毫米）远大于标定误差，先验 + 顶面判据要一起用。

`models/top_pic_2.jpg` 是 1280×720 原图，内侧圆面直径约 209 px。拍摄时从镜头到圆面约 145 mm，且没有数码变焦，可反推该画幅的像素焦距约 `145 × 209 / 30 = 1012 px`。实测距离是约数，因此这是一次粗标定。

默认焦距只接受未裁切的 16:9 画幅，并按实际帧宽度从 1280 px 等比例换算。其他画幅须显式传入该画幅标定后的 `focal_px`；裁切或变焦不同也应重新标定。距离指镜头到物料顶部平面，不是机械臂末端距离。相机畸变和物料倾斜也会带来误差。

## 使用与验收

其他模块直接传入一帧原始 BGR 图像即可；检测器应在连续处理帧时复用：

```python
from modules.vision.drive.material_locate import MaterialLocator

with MaterialLocator() as locator:
    report = locator.locate(frame)
    if report.present:
        for item in report.regions:
            print(item.name, item.confidence)
            print(item.center_x_px, item.center_y_px)
            print(item.x_mm, item.y_mm, item.z_mm, item.range_mm)
```

只跑一帧图像的离线工具从 `modules.vision.drive.material_locate` 导入；
**要连相机、连模型一起用**的上层代码请走会话接口，它负责打开 / 关闭设备：

```python
from modules.vision import Vision

with Vision.open(config_path="modules/vision/config.json") as vision:
    report = vision.locate()
```

`report.present` 由霍夫圆面决定。`item.confidence` 是 YOLO 类别分数，不是校准过的真实概率；YOLO 漏检时 `item.name` 和 `item.confidence` 均为 `None`，圆心与三维估算仍保留。`item.distance_mm` 与 `item.z_mm` 同义。相机坐标不是机械臂坐标，机械臂使用前需要另行标定相机与机械臂的相对位姿。

下游只该拿 `report.best`，不要自己取 `report.regions[0]`：圆面是按 x 排序的，第一个不一定是物料。`report.best` 可能是 `None`（没锁到顶面），这时不要拿旧值继续算逆解。`report.faces` 是"像顶面"的子集，`report.radius_window_px` 是这一帧实际用的窗口，排查时先看这两个。

在项目根目录运行以下 PowerShell 命令；预期检出原图中一个圆面，圆心约 `(602,419)`、半径约 `105 px`，并保存标注图：

```powershell
python -m modules.vision.drive.material_locate --image models/top_pic_2.jpg --save output/top_pic_2_circle_result.jpg
```

仅检查霍夫定位时，预期同样检出一个圆面：

```powershell
python -m modules.vision.drive.hough_lock --image models/top_pic_2.jpg
```

真机运行 `python test.py` 并选菜单 18；程序向相机请求 1280×720，按 `p` 打印结论、按 `q` 退出。菜单会打印这一轮用的是哪条路（颜色块还是霍夫）、工作距离先验和顶面直径；加粗绿圈（带 `*`）就是 `report.best`，灰色细圈是**被丢掉的候选**（不再让夹爪圆弧看起来像物料）。
